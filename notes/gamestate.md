- Saves: `$game_saves$` = `<appdata>\savedgames`; per save `<name>.scop` (engine ALife, SAVE_EXTENSION), `<name>.scoc` (Lua marshal, written by `alife_storage_manager.CALifeStorageManager_before_save`, lowercased name) and `<name>.dds` (thumbnail, a frame later). game_saved fires after both are written.

- The new game resets `[character_creation]` values and saves again during the load, so after game_teleport both copies show empty new_game_* fields.
- Quest tools (goal 25, xrGame/mcp_tasks.cpp, `mcp_register_tasks()` in OnAppStart): `tasks.get {id?, history?}` = engine task registry (title/description translated, type, received, PDA marker target) + one pcall'd Lua chunk per call (task_manager `random_task` or `get_task_manager()`, `task_info[id]`: stage, status, task_giver_id, last_check_task -> `pending`, forced_status; `task_ini` lines stage_complete/target_functor/status_functor/condlist_N/on_complete/on_fail). `infos.get {give?, remove?}` (csv) -> all known names. Supervisor: game_tasks / game_infos.
- The engine task registry never drops tasks: completed/failed ones stay (state, m_FinishTime) and are saved with the game, so history = registry (follows the loaded save: loading a save from before a completion drops it from history; survives supervisor reconnects and level changes). `get_task_state` only sees in-progress tasks (HasGameTask(id, true)), hence 65535 after completion. last_stage/giver of ended tasks come from a per-process cache (lost on exe restart).
- CGameTask::m_map_object_id defaults to 0 (= the actor) until a map location is set; target is valid only with `m_map_location` set (RemoveMapLocations sets the id to 65535).
- Task order in task_objects check_task: title/descr/target first, then condlists/status functor set `stage` -> the target for a new stage appears on the next check (0.5-1 s later). So `task_stage` (polled every 1 s from mcp_events' frame poll, `mcp_tasks_poll`) is reported one poll after detection with the then-current target: latency ~1-3 s. Cache reset on every level_unloaded (incl. same-level save loads), so loads never fire it; stage unknown to the script (task_info not loaded yet) is skipped.
- Poll cost: 45-140 us per poll with 1 in-progress task (vanilla and GAMMA; chunk compiled each time; max 324 us on the first run), nothing when no task is in progress. tasks.get 0.03-0.3 ms engine; 200 game_tasks + 200 game_infos: no script errors, private bytes unchanged (vanilla 4143.8 MB, GAMMA 11214 MB).
- Fetch tasks: the fetch section comes from `fetch_func` (`xr_effects.setup_generic_fetch_task`, run by the dialog) into `load_var(actor, id..'_fetch')`; giving the task from Lua without it never advances the stage. Test recipe: `save_var(db.actor,'esc_2_12_stalker_fanat_task_2_fetch','af_dummy_battery')` + `task_manager.get_task_manager():give_task(id, fanatic_id)`; hand-in equivalent `get_task_manager():set_task_completed(id)` (on_complete gives `<id>_done`). `xr_effects.set_task_stage(db.actor,nil,{id,'1'})` sets a stage.
