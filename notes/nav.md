# Navigation (game_nav / game_nav_map / game_move_to)
- Engine: `src/xrGame/mcp_nav.cpp` (`mcp_register_nav()` in OnAppStart, no-op without -mcp_port): nav.info / nav.at / nav.around / nav.path / nav.nearest / nav.grid / nav.overlay / nav.move_to / nav.move_status; supervisor block `game_nav / game_nav_map` after game_object.
- AI map = `ai().level_graph()`: nodes sorted by xz (`x * row_length() + z`, cell 0.7 m), several nodes per xz on multi-floor spots; links 0-4 (invalid link >= vertex_count). Lookups by cell use lower_bound (`navmap::cell_nodes`); `CLevelGraph::vertex_id` Msg-spams for out-of-box points, so check `valid_vertex_position` / use our own lookup.
- on_mesh = a node under x/z with |point.y - plane_y| <= 1.5 m; else nearest node centre (rings up to 50 m, then full scan ~2 ms on 625k nodes). snap() weighs height x3 in that nearest search (goal 32: an off-mesh target stays on its floor instead of snapping to the floor below).
- Path = engine `ai().graph_engine().search(level_graph, ...)` with NPC `CBaseParameters` (cost = cell per step, heuristic 2*cell*manhattan, weighted, fast: 0.1-7 ms across Cordon/Zaton); its vertex storage is fixed at 64K (max_visited 65500), beyond that an mcp A* with the same costs (`max_nodes`, default 400k).
- Decided: "any route?" from connected components (BFS over links) built once per level and cached: Cordon 625k nodes 11 ms, Zaton 1.85M nodes 42 ms (first path/at call per level). Cordon, Garbage, Zaton each have exactly 1 area, so no_route was never seen on real data.
- Corners: string pulling with `check_vertex_in_direction` (gallop + binary search) plus `navmap::clear` (goal 32: samples every 0.35 m keep `clearance` 0.32 m of linked AI map on both sides, ends excluded; offset nodes must be linked within 2 hops so thin walls do not count as map); corner points = node centres pushed 0.25 m away from missing 8-neighbour cells (`corner_point`). Waypoint heading = world yaw (state.get convention), bearing = relative to the current camera yaw.
- Cross-level: game-graph search from the actor's game vertex (`CGameLevelParams` trick: dest = u16(-1) widened, as `jump_to_level`); the level changer is matched via `CSE_ALifeLevelChanger::m_tNextGraphID` (exact) else the changer to that level whose `m_tNextPosition` is closest to the route's next vertex. Gotcha: in Anomaly changer destinations are not the graph's inter-level vertices (garbage_2 -> 762 vs route 763, 24 m).
- Locked changers in Anomaly = only the engine flag CLevelChanger::m_b_enabled (is_level_changer_enabled / enable_level_changer; saved with the object). The xr_effects enable/disable_level_changer are commented out; se_level_changer.enabled/hint are leftovers (hint stays level_changer_invitation). Walking into a disabled changer shows message_box_change_level_disabled (no OK). Accepting sends M_CHANGE_LEVEL with the changer's dest gvid/lvid/pos/angles = what _g ChangeLevel sends. Changer ids differ per install (vanilla esc->garbage_2 15364, GAMMA 15727).
- Overlay draws through `DRender->add_lines` (release-mode Lua gizmo path) from a hook after `ScriptDebugRender()` in CLevel::OnRender; lines are not depth-tested at that stage, so node visibility = static RayTest from the camera, 400 rays/frame in a seqFrame hook (rays must not run in render: GameThread runs then). Path/markers are drawn unoccluded.
- Overlay node list rebuilt when the actor moves 1 m (1.6 ms for 17.8k nodes at radius 60); render cost ~0.1 ms/frame at r20, ~0.27 ms at r60 (Cordon, uncapped ~400 fps). Off = one bool test. Reset when the MCP client changes; path/markers cleared on a level change.
- game_nav_map: engine nav.grid returns a byte grid (bit7 reachable, low bits height bucket) base64; the supervisor colours it and writes the PNG with stdlib zlib (decided over the engine WIC encoder: no engine change, easy overlays).
- move_to: `mcp_input::set_driver` tick is called in input frames only (frozen while MCP-paused, stepped frames advance it), keys via `mcp_input::hold_key` (released by input.release_all / client change -> mover aborts `keys_released`). Turn = actor camera Move (720 deg/s cap), forward held when within 50 deg, sprint_toggle tapped when not sprinting. Stuck = <0.3 m per 1 s of holding forward: open a shut door within 2 m (else a use tap; none next to an open door: it would close it), jump, replan, then `stuck`.
- Measured: 84 m in 30 s run, 16 s sprint; stepped dt 33: 300 frames -> 25.9 m, reached in 720 frames; NPC by id reached (1.5 m); aborts on ESC menu (dialog), game_input_release, stop.
- game_move_to defaults to sprint=True (goal 31; user request); game_state move = sprint while it runs.
- Closed physics doors are on the AI map, so paths go through them. Goal 28 doors in move_to: candidates per plan = kind-door objects (`mcp_world_is_door`) whose Center() is within 1.2 m of the path; `door_scan` each walking tick: within 2.4 m ahead -> door state via `mcp_door_state` (pcall'd Lua, <= every 250 ms per door); cabinet doors (ph_door `not_for_npc`) dropped; shut (closed/closing/locked) -> phases 1 walk to the stand point, 2 aim, 3 watch; open ones only recorded (action none).
- Passage door = kind door with leaf >= 0.7 m (2 x hinge-to-Center; cabinet/table doors 0.46-0.5 m, Cordon trader door 1.38, base doors 1.06, Bar arena codedoor 1.9); a shut one is acted on only if the rest of the path crosses its leaf segment (xz). Decided against ph_door `not_for_npc` as the cabinet filter: the locked Bar arena doors (codedoor_left) have it too.
- Measured (goal 28): 20/20 in-out round trips through Sidorovich's closed door on vanilla and GAMMA (in ~9 s, 1 press; the first trip of a session needed 2 presses both times, cause unknown); Cordon base door 1 likewise; Bar arena door (locked, no on_use) -> blocked_door after the avoid replan, 0 presses (13 s); trader door switched to its own ph_door@locked -> opened with 2 presses (unlock, open). Driver cost: no doors 3.4 us/tick avg (81 max), door on the path ~10-20 us avg, max ~1-9 ms (avoid replan with the mcp A*); path_doors 135-240 us per plan.
- Door stand point: on the closed leaf's normal through Center(), actor side, d = clamp(sqrt((2L+0.5)^2 - L^2), 1.2, 1.8), L = hinge (object Position = "door" bone) to Center(): outside the swing, inside use range. Gotcha: Sidorovich's door (door_trader, leaf 1.38 m, opens outward toward the village) opened from 1.3-1.5 m swept the actor ~1.2 m sideways behind the open leaf (stuck); opening then took ~4 s instead of ~0.7 s.
- Door aim: `look_toward` (yaw + pitch, 720 deg/s) at Center() (then +0.3/-0.3/+0.6 m, 4 aligned frames per point, 5 s cap); use pressed only after `HUD().GetRQ().O` == the door with range < 2 m on 2 consecutive input frames (CActor::UpdateCL takes the use target from that pick); pick on the door but >= 2 m -> forward held toward it.
- Door watch: poll every 100 ms; open -> walk to the gate (closed leaf Center) first, then the path (pitch levelled back); opening waits up to 6 s; still shut after 1.2 s -> 2nd press if the logic has on_use, else fail. Fail (locked without on_use, no_effect, pick_missed) -> AI nodes within 1 m of the door join `g_mv.avoid` (level_path then runs the mcp A* with the avoid list, graph_engine skipped) and replan; no route -> `blocked_door`.
- nav.use (supervisor game_use): the door aim/watch phases on any object without walking: outcome dialog_opened (TopInputReceiver during the watch), taken (H_Parent == actor), door_toggled, no_effect (1.5 s), out_of_range (> 2.5 m to the aim point, or pick on it beyond 2 m), pick_missed.
- Safety: main menu -> available:false no_level; 1667 calls through a Cordon->Garbage level change (loading answered by the supervisor, overlay rebuilt on the new level); 400 calls -> private bytes flat (+0 MB after the first 200).
- Shoot (goal 29, nav.shoot / nav.shoot_status, supervisor game_shoot): section "shoot" in mcp_nav.cpp; driver = `driver_tick` (mover_tick + shoot_tick); a shoot and a move/use replace each other (both turn the camera). Target looked up by id every tick; ends on death/gone/level change (g_pGameLevel identity, so same-level loads too)/dialog/client change/`mcp_input::release_count()` change.
- Shoot aim: centre of the bone's collision shape (SBoneShape box/sphere/cylinder via LL_GetData(b).shape in bone space x LL_GetTransform x XFORM); head = bip01_head|head, chest = bip01_spine2|spine1|spine|spine, else a bone name, fallback bbox centre ("center"). Monster bone names unverified live.
- Shoot camera: deadbeat camera correction (1080 deg/s cap) + filtered bias (0.25, +-10 deg, only while the weapon is steady) = angle between the weapon fire ray and the camera ray (g_firepos/g_aimpos fire from the barrel). Recoil untouched, re-aimed every tick.
- Fire ray = `CActor::GetPick()` (attached HUD item's PP, updated in player_hud OnFrame by CHudItem::UpdatePick; g_fireParams hands bullets its start/dir before dispersion). Decided: fire only while its result.O == target for 2 ticks and range <= GetFireDistance; barrel_blocked -> never fire.
- Shoot LOS: when off target, every 100 ms `HUD().DoPick` from the fire-ray start to the aim point (pick rules: objects stop, VisTransparency geometry passes; a hit on an object whose H_Parent is the target = clear); blocked 1.5 s -> los_blocked with blocker {what creature/object/level_geometry/barrel_blocked, id, name, section, material, distance}.
- Shoot fire control: auto (GetCurrentFireMode < 0) holds fire for `burst` rounds, released when off target, 150 ms gap, released after 600 ms without a shot (safe-mode press); single/fixed-burst: 1-frame tap when eIdle, >= 100 ms apart. Shots = magazine drops outside eReload. Empty -> reload tap (<= 2 tries, 3 s apart) else out_of_ammo; IsMisfire -> reload tap (engine TryReload unjams) else jammed. Done waits 500 ms for rounds in flight; death waits <= 1 s for killer_id.
- Hit attribution: `g_mcp_on_hit` pointer in Entity.cpp called at the top of CEntity::Hit (null without -mcp_port); counts hits with whoID == actor under a critical section (thread of Hit not verified). Script-side damage (GAMMA on_before_hit) may change power; health before/after is the outcome measure.
- Unverified live (goal 29 shipped without live tests): 1-frame tap fires singles, burst behaviour, camera convergence under recoil / GAMMA firepos, hook reached for stalker/monster bullets, killer_id within 1 s, reload unjams (vanilla/GAMMA), NPC-held weapon blocking the pick, monster bone names, out_of_range distances.
- Goal 32 move_to robustness: corner reached at < 0.5 m xz and |dy| < 2 (was 0.7 m, xz only); the skip-ahead check also needs `clear`; the target snaps on its floor; snapped node >= 2.4 m off the target's y -> `unreachable` target_floor_off_mesh at once; off-map target (goal_on_mesh false) -> aim at the snapped goal (not into the wall) and `unreachable` target_off_mesh at the path end; under/over the target at the path end -> 1 replan then `unreachable` wrong_floor; 3 s without progress while turning in place -> replan (was never caught: forward not held -> no stuck check); stuck replans ending within 1 m of the previous one 3x -> `stuck` (was a jump/replan loop until timeout); after a door opens and the gate is reached the path is replanned from the doorway; after a stuck / doorway replan no skip-ahead until the next corner is reached (`no_skip`).
- Look-ahead rays (goal 32, `obstacle_scan` in the input tick, every 100 ms while forward is held and no door phase): 6 RayPick rqtBoth, 1.8 m toward the aim (knee 0.45 / chest 1.2 m, centre and +-0.3 m). Obstacle = object not CEntityAlive, not a door, not CInventoryItem, not H_Parent'ed, not the move target; same id on 2 casts -> AI nodes inside its visual box (XFORM, grown 0.4 m; not within 0.8 m of the actor or 0.5 m of the goal; Radius > 6 m skipped) join g_mv.avoid and replan; no route -> avoid restored. g_mv.avoid is kept sorted (mover_plan) and long_astar uses binary_search.
- Reports (goal 32): goal/goal_on_mesh, blocker (ray hit via blocker_json; on final `stuck` a probe of what is ahead or none_ahead), recovery list (use, jump, replan, replan_turning, replan_wrong_floor, skip_corner, door, avoid:<id>, avoid_no_route:<id>, obstacle_off_map:<id>), tick_us {avg, max}.
- Measured (goal 32, vanilla): Agroprom 5 stair/upper-floor routes before 8/10 (ag4 stuck 2/2 at 12.05,0,-4.12), after 5/5 with 0 stuck checks; Bar upper floor (154,10.3,108.5) reached both; off-map upper target 2.3 m beside the floor: before `stuck` after 53 s grinding, after `unreachable` target_off_mesh; target 7 m above any floor -> unreachable at once. Niva spawned in a Bar alley: seen at 0.6-1.2 m, avoided, reached (detour 68 m: the alley is blocked). Driver cost 10-20 us/tick avg, max ~0.1 ms walking, 0.4-0.7 ms on an avoid replan (mcp A*). Sidorovich door from the village (-221.08,-19.94,-168.18): final build 13/13 in + out trips reached (~18-21 s, 1 press; baseline exe 2/3 in). Cordon 190 m route there and back: reached, 0 stuck checks.

- Gotcha (goal 32): with sprint as default (goal 31) the actor overshot the door stand point into the leaf's swing; Sidorovich's door then took ~5 s to open and swept the actor into the pocket between the open leaf and the wall (wedged at -248.63,-24.8,-133.15; baseline exe 1/3, a first goal-32 build 4/7 trips `stuck`).
