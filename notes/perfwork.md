## Render candidates (investigator, from the profile)

- R2 dx10SamplerStateCache: every set_States re-sends 16 samplers on 6 stages (PrepareSamplerStates ignores current state). Cache bound sampler pointers per stage/slot; reset in Invalidate and after ComputeShader.cpp CSSetSamplers. Est. 2-3.5 % both.
- R3 CLevel::OnRender loops all objects calling DBGDrawPhysicsShell with debug flags off: guard with psDeviceFlags2 (0.7-1.0 %).
- R4 constant-buffer bookkeeping per draw: flush_cache scans 84 slots, set_Constants copies/nulls/reassigns 84 ref_cbuffers (dx10r_constants_cache.cpp:72-97, dx10R_Backend_Runtime.h:549-579). Est. 1.5-3 %.
- R5 dx10ConstantBuffer Access() always marks dirty -> Map/memcpy/Unmap per draw even for an unchanged LOD factor (dx10ConstantBuffer_impl.h:5-15): compare before marking. Est. 0.5-1.5 %.
- R6 sampler states destroyed/recreated twice per frame by disable_aniso / phase_scene_begin (SetMaxAnisotropy): keep both variants. 0.3-1.2 %.
- R7 ApplyVertexLayout std::map find per draw: one-entry cache (0.4 %). R8 add_Static_MultiFrustum heap vector per node + double probe of m_static_seen (0.3-0.8 % GAMMA). R9 state cache re-hash + GetDesc scan per rasterizer/DS/blend change (0.3-0.5 %). R10 rain: normalize before the cull test (0.1-0.3 % plain).
- Rejected: RenderPacket sort changes (order of equal keys), skipping set_States, partial CB upload, tree benders skip, HOM (uses ::Random), larger grass batches (shader), hoisting grass alpha fade (per-pass on purpose).
- Fine already: texture slot cache, SRV dirty ranges, RS/DS/blend pointer cache, dsgraph pointer filters, R_constant_table::get, PROF_EVENT compiled out.

## Later findings
- GAMMA at the test settings is GPU-limited (~128 fps): judge CPU work by frame ms minus the present phase, not fps.
- The 170-230 ms GAMMA frame per 5 min run = first draw of a weapon after a load: `CHudItem::HudItemData()` (HudItem.cpp:955) lazily builds the HUD item -> `attachable_hud_item::load` (player_hud.cpp:619) -> `Render->model_Create` loads the HUD model from disk on the main thread. 3DSS (`z_3dss_shader_switcher.script` get_owner_materials -> game_object:get_shaders(true) in CActor_OnChangedSlot) triggers it one frame before the engine would. The getters themselves are cheap. Candidate S2: `models_PrefetchOne(item_visual)` with `Render->hud_loading = true` for actor slot items during level load (base models survive level changes; spawn prefetch never warms HUD visuals). VSDiagnostics CpuUsageLow is only 100 Hz: too coarse for a spike; use game_lua_profile windows (worst_frames) to catch spikes.
- A second luabind Lua state exists (renderer `LSVM`, ResourceManager_Scripting.cpp); per-state caches in luabind must be bound to the game state explicitly (done in F5 via `pcall_cache_reset` from CScriptStorage).
- `vs_to_layout` is keyed by the signature blob; `_DeleteVS` erases that signature's layouts from every declaration (R7 resets its memo there).
- dx10ConstantBuffer keeps a CPU copy; `AccessDirect` always marks dirty and callers must write before the next Render (grass `c_ExData` relies on the `array` re-map in the same $Globals buffer).
- `smart_cast<T*>(CObject*)` falls back to RTTI unless smart_cast.h has a specialization; CObject already declares cast_inventory_item / cast_weapon / cast_missile etc.
- Any new writer of `xrServer::entities` must go through `entity_Insert` or clear `m_entity_by_id`; any new writer of `m_a*Constants` must rebuild `m_aBoundCBuffers`.
- GAMMA new game shows "You feel a splitting headache..." (a psy event at start): the source of the arszi_psy death in test sessions.
