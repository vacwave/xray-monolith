# Python MCP supervisor (`mcp/`)
- Single file `mcp/anomaly_mcp.py`; MCP SDK 2.x (`mcp>=2.3,<3`): FastMCP is renamed `mcp.server.mcpserver.MCPServer` in 2.x (`mcp.server.fastmcp` raises). Run: `py -3.11 mcp/anomaly_mcp.py`; `.mcp.json` registers `anomaly` with a repo-relative path (Claude Code must start in the repo/worktree root).
- SDK 2.x hides the text of non-`ToolError` exceptions ("Error executing tool X"): the `@tool` wrapper re-raises everything as `ToolError("<Type>: <msg>")`. Client side: `CallToolResult.is_error` (not `isError`).
- Tools are async; blocking work runs via `anyio.to_thread.run_sync`. Each instance: socket reader thread (responses by id + `log` events) and a process watcher thread (WaitForSingleObject via ctypes).
- Slots: `%LOCALAPPDATA%\anomaly-mcp\slots\<profile>-<n>.lock`, `msvcrt.locking(LK_NBLCK)` on byte 0, held by the supervisor until the game exits (watcher releases) or game_stop. Caps: env `ANOMALY_MCP_MAX_VANILLA/GAMMA` > `%LOCALAPPDATA%\anomaly-mcp\config.json` > 3/2. Profile gamma iff game_root is C:\GAMMA.
- Instance id = slot name (`vanilla-1`); appdata `<repo>\.mcp-run\<id>\appdata` (reused; user.ltx overwritten from `mcp/templates/user.ltx` each launch, shaders_cache seeded once). A relaunch into the same slot replaces the dead entry.
- Launched games go into a KILL_ON_JOB_CLOSE job object, so they die with the supervisor (keeps caps honest); on stdin EOF the supervisor first game_stops them gracefully. Attached games: no slot, no job.
- Ring: deque of (seq, line, arrival time; 0 for fills), 20k. Live events with seq <= last_seq are dropped (already fetched); a jump > 1 triggers a `log.tail {"since": prev}` fill on a side thread; merges rebuild sorted by seq. Connect always does `log.tail since=last_seq`. Log rate = live arrivals in the last 10 s.
- Output safeguards (`bound`): collapse consecutive repeats `×N`, clip lines to 2000 chars, cap 20k chars (exec keeps head, log/status keep tail), `omitted` explains; exec adds the engine's `truncated`.
- game_stop: `console.exec quit` (replies, then exits in <1 s), wait 30 s, TerminateProcess. Externally killed game → exit code 1, alive false, buffer kept.
- Verified timings: launch → connected + engine.info ≈5 s (menu still loading, frame ~2); `new_game` → level `fake_start` in engine.info after ≈8 s; 5000-line spam exec ≈0.1 s.
- Quick exit (code 0 within 15 s) = presence mutex (same exe dir + appdata) or startup failure; reported with the newest log file's tail (with a mutex block that is the other instance's log).
- Gotcha (seen once, not reproduced): a launch hung with no `logs` dir and no `mcp_port` for 120 s. Now game_launch dumps it (`dumps/launch_timeout_<pid>_<ts>.dmp`, path in the error) and kills it.
- Gotcha (build): never pipe MSBuild into `Select-Object -First N` — it stops the pipeline and kills MSBuild mid-build, leaving cl.exe orphans.
- Config is `load_config()`: DEFAULTS < config.json < env `ANOMALY_MCP_<KEY>` (max_vanilla, max_gamma, hang_timeout_s 30, load_hang_timeout_s 600, dump_keep 5, dump_cap_gb 40).
- Crash record (`collect_crash`, idempotent, under crash_lock): built when the reader gets a `crash` event (the reader then closes the socket) and again by the watcher on exit (crash event, or nonzero exit while not stopping). Fields: reason (`crash_summary`), exit_code_name, stack (`compact_stack`: no StackWalker headers/xrDebugNew frames, basenames), dumps, .log tail and buffer tail with the ~700-line console-variable dump collapsed (`drop_cvar_dump`).
- Dumps go to `.mcp-run/<id>/dumps`: engine .mdmp (from appdata/logs, mtime >= launch), WER `<exe>.<pid>.dmp` (waits <=15 s for it after a crash-like exit, then for its size to settle), `game_dump` files. `prune_dumps(profile)` keeps the newest dump_keep within dump_cap_gb across `<profile>-*/dumps`.
- WER: `setup_wer.ps1` (admin, once) creates HKLM LocalDumps\AnomalyDX11AVX.exe (DumpFolder %LOCALAPPDATA%\anomaly-mcp\wer, DumpCount 10, DumpType 0, CustomDumpFlags 0x1965) and grants the user SetValue. game_launch sets DumpType 2/0 from `full_dumps` (global per exe name: last launch wins). Missing key → warning in game_launch/game_status and at startup. Mid dump ≈ 91 MB at the main menu.
- `dump_exception` parses a minidump's exception + module list streams (code, fast fail code, module+offset); used for WER dumps so `__fastfail` crashes get a reason without an engine event.
- Hang monitor thread per watched instance: `engine.heartbeat` every 2 s (timeout 5 s); stall = time since the frame last changed (no reply counts as stalled); hung when > hang_timeout (load_timeout while loading). Verified: `while true do end` → hung after ≈36 s. game_stop kills a hung game at once; status skips engine.info while hung.
- game_dump: MiniDumpWriteDump via ctypes (QUERY_INFORMATION|VM_READ|DUP_HANDLE, flags MID_DUMP_FLAGS 0x1965), ≈90 MB, 0.2 s at the menu.
- game_restart: stop if alive, release and re-acquire the same slot index (`acquire_slot(profile, index)`), `launch(**launch_params)`; attached instances cannot restart.
- game_teleport (block `TP_*` / `teleport` near the end): pure lua.exec/console.exec, no engine or gamedata changes. Menu → writes the faction-select config (difficulty/economy 1, story on except zombied, name MCP_Agent, stock kit) and starts the game; target level's start location (faction's own, else any faction's) or, if none, stays on fake_start and then level-changes. Two loads either way.
- game_teleport decisions: in-game `faction` only switches the community in place (noted in the result; clean faction start = game_restart + game_teleport); cross-level spot = start location, else a smart terrain's graph vertex (bases first), else with `position` the nearest graph vertex then set_actor_position; off-map positions snap to the nearest AI node within 30 m; a missing PDA is given (device_pda_1).
- game_teleport waits: heartbeat `loading` false → lua probe level == target, `afterFirstUpdate`, alive; dead game → error with the crash reason; default timeout 600 s.
- RaiseFailFastException exits 0xC0000602 (not 0xC0000409); a real `int 29h` gives 0xC0000409 with the fast fail code in ExceptionInformation[0].
- `game_perf(instance, seconds=5)`: one contiguous block before `main()` (`perf_window`: perf.start, sleep, poll perf.report); fields in `perf.md`. `game_launch(exe=...)` already takes an exe path (used to test from `C:\Anomaly\bin_g9`).
- `game_lua_profile(instance, seconds=5, top=30, mode=time|calls|alloc)`: block after game_perf; `perf_window(..., **extra)` passes `lua_profile`/`top` to perf.start; result = window summary + game_perf Lua/GC/heap + the engine's `lua_profile` (see perf.md).
- Game events (block `EventBuffer` / `game_events` before game_teleport): per instance `inst.events`, 5000 events (seq, time, type, frame, data) merged by seq; live `game` events with seq <= last are dropped, a jump > 1 fills via `events.tail {since}` on a side thread; connect always fills since last_seq (so reconnects lose/duplicate nothing while the engine ring of 1000 still holds them; otherwise `lost` counts the missing ones).
- `game_events(since, types (fnmatch), limit<=500)`: with since the first `limit` after it (page by last_seq), else the newest; string fields clipped to 4000 chars. `game_status.events` = counts since the previous status call; console_exec/lua_exec/game_teleport add `script_errors` (occurrences since the previous such call, summed since_last); game_last_crash adds the last fatal script_error.
- `game_screenshot` (block before game_perf): heartbeat loading check, `screenshot.begin`, poll `screenshot.get` every 10 ms until `timeout` (10 s); returns `[TextContent(JSON meta), ImageContent]` (annotation `list[TextContent | ImageContent]`, from `mcp.types`); relative save_path -> `.mcp-run/<id>/screenshots/`, parent dirs created. Opening the 3D PDA via `ActorMenu.get_pda_menu():ShowDialog(true)` or kACTIVE_JOBS press showed nothing in the frame (inventory via `level.press_action(bind_to_dik(key_bindings.kINVENTORY))` works). Cause: the PDA was in the backpack, not slot 8; fixed in game_teleport (see input.md).
- `game_input(steps, wait=True, timeout=120)` / `game_input_release` (block `game_input` before game_screenshot): input.run then poll input.status every 20 ms (TimeoutError during loads is retried until the deadline); on timeout calls input.release_all and errors. `steps=[]` returns the status.
- game_teleport TP_FINAL moves the PDA into slot 8 (`move_to_slot`) when the slot is empty; a PDA it had to create (alife_create_item, async) is not slotted until the next teleport call.
- Test harness pattern (scratch, not in repo): a persistent MCP stdio client serving tool calls on a local TCP port keeps one supervisor+game across many one-off scripts.
- `game_objects` / `game_object` (block `game_objects` between game_state and game_input, `world_call`): kinds validated against WORLD_KINDS; floats/bools converted to strings/ints for the engine; heartbeat loading/hung -> `{available:false, reason}` without touching the main thread. Fields in world.md.
- `game_state(sections)` (block before game_input): heartbeat `loading` -> `{mode: loading, source: supervisor}` without touching the main thread; hung -> `{mode: hung}`; state.get timeout 3 s, then heartbeat again (load started meanwhile -> loading) else error. Measured during game_teleport: loading answers in ~3 ms; slowest call 1.4 s (first frames after a load). Use time.perf_counter for ms timings (time.monotonic ticks at ~15.6 ms on Windows).
- game_save / game_load / game_saves (block `game_save` after game_teleport; reuses `tp_wait`): pure console/lua.exec. Save names cleaned to `[A-Za-z0-9_.-]` (spaces would break `-start server(...)`); save done = `game_saved` event with that name (~0.12 s). Load done = game_loaded (name) -> level_loaded -> actor_spawned events after it, then tp_wait on that level; ~4 s same level, ~6 s other level, ~8-12 s from the menu / at launch. Death screen: stops the tutorial first (see gamestate.md).
- game_load: game died -> result `loaded:false, crash` (last_crash record) + `missing_sections` from `! Can't create entity` log lines since the load; timeout -> TimeoutError, the game keeps loading and ends up usable.
- game_saves: list from the instance's savedgames dir (+ level/game_time/health via CSavedGameWrapper when the game runs, ~70 ms for 8 saves), `import_from` copies .scop/.scoc/.dds in (source untouched), `delete` only inside the instance's savedgames. game_launch(load=) needs the save already in the slot's appdata (no spaces) and waits like game_load (result.load); game_restart keeps load in launch_params.
- Gotcha: saves live in the slot's appdata, so a launch that lands in another slot (another session holds vanilla-1) sees none of them; copy them over with game_saves(import_from=<other slot>\appdata\savedgames\<name>.scop).
