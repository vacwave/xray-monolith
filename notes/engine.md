# Engine loop, threading, startup
- Frame: `CRenderDevice::on_idle` device.cpp:331 → `FrameMove` :662 runs `seqFrame.Process` on main thread :717; then secondary_tasks, `seqRender` :526, `secondary_tasks.wait()` :543.
- Main-thread per-frame hook: `Device.seqFrame.Add(this)` (see xrGame/GamePersistent.cpp:95) or `Device.AddSeqFrame(f,false)` device.cpp:869 (`true` = MT list — don't use for game work).
- Gotcha: `GameThread` EngineThreading.cpp:124 is a background task running scheduler, seqParallel, seqFrameMT and parallel Lua GC — Lua is not main-thread-only.
- Task groups are MSVC PPL `concurrency::task_group` (xrCore/_thread_types.h:18), not TBB.
- Startup: WinMain x_ray.cpp:1271 → WinMain_impl :971 → Core._initialize :1107, InitEngine :173, InitConsole :239, Startup :589.
- In Startup: `Device.Create()` :648, `Init_Discord` :662 (model for starting a service thread), `Device.Run()` :675; shutdown after Run returns :677-715, `destroyEngine` :310.
- Flags: raw `strstr(Core.Params, "-start ")` x_ray.cpp:639; typed `ECoreParams` xrCore/xrParams.h:3 filled in xrParams.cpp:26, test via `Core.ParamsData.test(...)`.
- `-appdata <dir>`: `xrParams::GetAppDataArg` (xrParams.cpp; quoted `"..."` for spaces, else up to next space; `_fullpath`-normalized, `\`, no trailing slash). Applied in `CLocatorAPI::_initialize` when the `$app_data_root$` line is parsed, so `$logs$`/`$game_saves$`/... follow; dir created via `VerifyPath`.
- user.ltx loads (`CCC_LoadCFG`, falls back to `$fs_root$`) and saves (`CCC_SaveCFG`) via `$app_data_root$`; logs and minidumps via `$logs$`; shaders_cache under app_data_root → all follow `-appdata`.
- Presence mutex (x_ray.cpp, `NO_MULTI_INSTANCES`) = crc of exe dir, chained with crc of lowercased `-appdata` path when given. A blocked instance exits silently with code 0 (WinMain ignores WinMain_impl's return).
- Focus loss: `CRenderDevice::OnWM_Activate` device.cpp; `g_always_active` (rsAlwaysActive) or `-mcp_port` keeps `b_is_Active` TRUE (not in exclusive fullscreen, g_screenmode 2). `b_is_Active` gates rendering (`on_idle`) and seqAppActivate/Deactivate; `dwFrame` advances even when inactive.
- Core.Params is the lowercased command line; WinMain's lpCmdLine keeps case and is available before Core._initialize.
- Silent runs: `Device.IsSilent()` = `-mcp_port` without `-showwindow` (`ECoreParams::showwindow`). Window is created then `ShowWindow(SW_SHOWMINNOACTIVE)` + `b_is_Active = TRUE` (Device_Initialize.cpp); no splash (x_ray.cpp checks raw lpCmdLine, Core not up yet).
- Window changes go through `CRenderDevice::SetWindowStyle` (keeps WS_VISIBLE|WS_MINIMIZE when silent), `SetWindowRect` (silent: SetWindowPlacement of the restored rect, stays minimized/inactive) and `UpdateClientRect` (silent: no ClipCursor; iconic → client size = dwWidth/dwHeight). Used by Device_create, Device_destroy (Reset, ChangeOutputMonitor), dx10HW `updateWindowProps`, `rs_screenmode`.
- Fixed (goal 30): the window is created `WS_EX_TOPMOST` (Device_Initialize.cpp); `updateWindowProps` clears it via `SetWindowRect(HWND_NOTOPMOST, ...)`, but the silent branch ignored `after`, so a silent window restored by the user stayed on top of everything (alt-tab made another window foreground but it stayed behind). Silent `SetWindowRect` now passes `after` to its final SetWindowPos (NOMOVE/NOSIZE/NOACTIVATE, stays minimized).
- MCP runs (`-mcp_port`, silent or -showwindow): `SetWindowStyle` adds WS_SYSMENU|WS_MINIMIZEBOX to WS_POPUP (borderless) styles, so Win+Down, Win+M and the taskbar/system-menu Minimize work. Non-MCP styles unchanged (0x94000000).
- Gotcha: while the game window has focus, DirectInput's exclusive mouse (DISCL_EXCLUSIVE|FOREGROUND, vanilla) swallows real clicks, so taskbar clicks do nothing until focus leaves; keyboard (Alt+Tab, Win, Win+Down) works. Measured with mouse_event clicks on the UIA-located taskbar button (`X-Ray Monolith Engine - 1 running window`).
- Gotcha: DXGI `IDXGISwapChain::ResizeTarget` (dx10HW `CHW::Reset`) restores+activates a minimized window → skipped when silent (windowed only; ResizeBuffers sizes the buffers).
- Silent mode clamps `rs_screenmode fullscreen` to borderless (CCC_Screenmode) and skips SetForegroundWindow/SetActiveWindow (device.cpp Run, Device_create, updateWindowProps) and the main-menu ClipCursor.
- Rendering never checks IsIconic/occlusion: on_idle renders when `b_is_Active && Begin()`; Present's DXGI_STATUS_OCCLUDED is a success code, ignored. `Device.dwRenderedFrames` counts frames through seqRender+Present.
- Non-crash dialogs: only dx10HW "Failed to initialize graphics hardware" MessageBox (device creation failure, then TerminateProcess(0)); in MCP mode skipped, exit code 1.
- Level start without UI: `-start server(all/single/alife/new) client(localhost)` loads `fake_start` (new-game level) in ~10 s. `-load <save>` at startup fails ("ALife simulator has not been started yet"); `-start server(<save>/single/alife/load) client(localhost)` works (game_launch load=).
- Confirmed save/mod mismatch: `CALifeObjectRegistry::get_object` skips objects whose section is missing (`! Can't create entity '<sec>'`, F_entity_Create returns null), their saved children keep the dangling ID_Parent and `register_object` dereferenced the null parent. Now a `Debug.fatal` "[LSS] item [name][id] (section) has parent id N, which is not in the saved game" (alife_simulator_base2.cpp). The user's `1` / `bench_g1` are GAMMA saves: `1` misses 8 `zc_cs_*`/`zc_esc_guide` sections (GAMMA mod "Zone Chronicles"), `bench_g1` 152 sections (wpn_sr1m, tb_stsh_*, fast_travel_zone ...).
- The main thread blocks while a level loads, so MCP calls get no reply until it finishes (several minutes for a save load).
- Fixed (upstream bug, goal 22): quit within the 60 precache frames after an in-level save load (`game_sv_Single::restart_simulator` -> `Device.PreCache(60)`, the only PreCache that runs with a level and no loading events, so the only one that creates `precache_light`, device.cpp) left `precache_light` alive; its static destructor ran after the global `RImplementation` was destroyed and `light::~light` erased from the dead `v_all_lights` set -> double free, exit 0xC0000374 after "Destroying Direct3D" (dumps 19452, 7408; 4/4 repro). Now dropped in `Startup` right after `Device.Run()`/`mcp::stop()` (x_ray.cpp), before the spatial DBs are deleted: 0/40 (plus 0/2 with an earlier version).
- Gotcha: the light must go before `xr_delete(g_SpatialSpace*)` in Startup: releasing it in `CRenderDevice::Destroy` (first try) ran `set_active(false)` -> `ISpatial::spatial_unregister` on the deleted spatial DB -> AV (1/26).
- Gotcha: new-game / level-change loads call PreCache inside a loading event, so they never create precache_light; quitting during their precache was always clean (10/10).
- Open (1 dump, 18664, not reproduced): another shutdown double free in `CRender::destroy` -> `~CModelPool` -> `~_Tree` of `Registry` (its head node already freed, contents intact). `Registry`/`Pool` are changed in Create/DeleteInternal/Discard without a lock (only `Models` has ModelsLock); suspected cross-thread model create/delete race (MT upstream), no evidence of MCP involvement. Not reproduced in 70 later quits (40 right after an in-level load, 10 right after spawning 36 monsters, 10 with profile+screenshot+input+MCP pause active, 6 after a load, 4 at the menu); no other thread touches the pool at CRender::destroy.
