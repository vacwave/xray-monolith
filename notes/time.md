# Time control (MCP pause, step, time factor)
- Engine: `src/xrEngine/mcp_time.{h,cpp}` (namespace `mcp_time`), registered in `mcp::start`; one hook `mcp_time::on_frame_time()` in `CRenderDevice::FrameMove` right after the timer block (before seqFrame). Unused = one bool test per frame.
- Methods: `time.get` -> {mcp_paused (requested), applied (in effect), paused (Device.Paused), main_menu, loading, frame, time_global, time_async, time_factor, step_id, step_done, steps_left, step_dt_ms, step_cancelled?, time_factor_orig?}; `time.pause {"on"}`; `time.step {"frames":1..100000,"dt_ms":1..100 (20)}`; `time.factor {"value":0.01..100}`. Pause/resume/steps take effect at the next frame: poll time.get (applied / step_done >= step_id).
- Existing engine pause (what ESC uses): `Device.Pause(on, timer, sound)` -> `g_pauseMngr` pauses the only two CTimer_paused (Device.Timer, TimerGlobal) -> fTimeDelta 0, dwTimeGlobal/TimerAsync (and game time, which reads TimerAsync) frozen; scheduler/GameThread, object updates, net_Update (NET_processor), level sounds, CLevel key input (except ESC/pause/console) skip while `Device.Paused()`. Frames, rendering, seqFrame (MCP handlers), console keep running; limiter caps paused frames to the monitor refresh (or r__framelimit).
- Decided: MCP pause = `Device.Pause(TRUE,TRUE,TRUE,"mcp_time")` + `bShowPauseString = FALSE` (no "paused" text in screenshots). Tracked separately (want/applied).
- Decided: ESC menu over an MCP pause keeps it: MainMenu deactivation always unpauses (mm_deactivate2), so the hook re-pauses in the next frame and shifts TimerGlobal back to its frozen value (no time leaks). Any other unpause of the MCP pause by the game (pause key, console `load`, scripts) ends the MCP pause ("resumed by the game"). Pause requested while the menu is open joins its pause.
- Decided: a level change/unload or loading (`g_pGameLevel` changed, `pApp->IsLoading()`) releases the MCP pause; the supervisor's game_teleport / game_load lift it first and re-pause after (loads need net_Update, i.e. an unpaused device). A raw lua ChangeLevel while MCP-paused just waits until resume.
- Decided: steps are always fixed-dt: a step frame unpauses pauseMngr (sound stays paused) but keeps TimerGlobal individually paused and advances its frozen value by exactly dt (`timer_access` pointer-to-member access to CTimerBase::qwPausedTime/qwPauseAccum, no FTimer.h change); dwTimeGlobal/fTimeGlobal/dwTimeDelta follow, fTimeDelta = dt. The frame after the last step frame is paused again. Verified: 30 frames x dt 20/33/7 -> exactly 600/990/210 ms sim and 3600/5940/1260 ms game time each, frozen in between.
- Steps are cancelled (step_cancelled) when the main menu opens or the pause is lifted; time.step is refused in the main menu / without a level.
- Decided: safety = reset on client change (mcp::client_id() polled in the hook; also checked in every time.* handler): pause released, steps cancelled, time_factor restored to the value before MCP changed it. No timeout. Verified: killing the supervisor while paused + 2x speed -> game runs at 1x.
- time.factor runs console `time_factor` (CCC_TimeFactor: Device.time_factor = both timers, also psSpeedOfSound). Measured: 0.25/1/4 -> 250/1000/3998 sim ms and 1.5/6/24 game s per wall s; NPC metres per wall s 1.9/6.6/17.9; fps unchanged.
- Game clock rate (in-game s per sim s) = `level.set_time_factor` (supervisor Lua, not engine). Gotcha: surge_manager's `main_loop` resets it every second to its local `normal_time_factor` (alife.ltx time_factor, 6) outside surges/psi storms; the supervisor also sets that upvalue (debug.setupvalue via surge_manager.on_game_start -> main_loop). Reset by the next Lua state (level change / load).
- Gotcha: `level.get_time_factor()` / `game.time()` without a level crash with an AV in C++ (not a Lua error): check `level.present()` first.
- Input (mcp_input): durations are wall ms when time control is unused (unchanged), else simulation ms (dwTimeDelta); frozen (no ticks, no hold events) while Device.Paused outside menus/console; menus and console run in wall time, plus one frame after they close (so an ESC/TILDE tap that closes one still releases).
- Measured: 500 ms forward hold: real time 1.26-1.27 m, stepped dt 20/10 1.25-1.27 m, dt 33 1.32-1.35 m (hold rounds up to 16 frames = 528 ms). Look +90 exact, fire while stepping uses ammo, input frozen while paused without steps.
- Measured: game_step(frames 10, input, screenshot 512 px, state) ~770 ms per call with r__framelimit 30 (10 frames = 333 ms of it); paused frame-hook round trips ~33 ms at that cap.
- Paused screenshots differ only in HUD elements animated in wall time (battery icon, ~1400 px); the 3D world is identical. Hang monitor: frames keep advancing while paused (verified 65 s, hung false).
- Gotcha (not from this goal): graceful quit sometimes ends with 0xC0000374 heap corruption at ntdll+0x112fc5 during "Destroying Direct3D"; seen 3x (one in a game started before this goal's exe existed), not reproduced in 5 other quits.
