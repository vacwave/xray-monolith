# Options menu entries (D6)
- Entries: `gamedata\scripts\modxml_options_dlss.script` adds one block to Video > Advanced (after SMAA, before the next section line; else at the page end): title, `r4_dlss`, DLSS status line, `r4_upscale_sharpness`, `r4_dlss_preset`, `r4_render_scale`, `r4_dx12_present`, `r4_framegen`, FG status line, `r4_reflex`, Reflex status line; plus a note above MSAA "MSAA and SMAA are ignored while DLSS is on" (only while `r4_dlss_status` = on). All rows have precondition renderer_r4.
- Flags: DLSS mode / preset / render scale `vid=true` (menu runs vid_restart on close), bridge + framegen `restart=true` (restart message box), sharpness and Reflex runtime. Values go to user.ltx by `cfg_save` (all are normal CCC_Integer/Float/Token, saved by Status; no flag fix needed).
- GAMMA ships its own `ui_options.script` (G.A.M.M.A. UI, Warfare, translations), so we never override it: the script is a DXML `modxml_*.script` (dxml_core calls its `on_xml_read`), wraps `ui_options.init_opt_coder` (init_opt_base calls it last; we insert rows, idempotent by id `dlss`, inside pcall, then call the original) and rebuilds once if options were already built. Same mechanism style as `ui_options_modded_exes.script` (which wraps init_opt_base).
- The framework has no disabled state: `precondition` hides a row; status lines are plain-data `type="desc"` rows (`status_cmd`, precondition_1 `{has_note, cmd}` = shown only for strings containing ":"); the text is built in a wrapped `ui_options.UIOptions.Register_Desc`.
- Gotcha: ui_options draws a deep copy of the page (`copy_table` into `last_curr_tree`), so a precondition that mutates the original row (closure) changes nothing on screen (empty gap); a row referencing itself makes copy_table recurse (stack overflow).
- Status exposure: read-only console commands `r4_dlss_status`, `r4_framegen_status`, `r4_reflex_status` (`CCC_RenderStatus`, xrRender_console.cpp, USE_DX11 only, Save() empty so never in user.ltx; Execute logs the value). Before `HW.pDevice` exists they return "unknown: render device not created yet". Lua: `get_console_cmd(0, name)` = nil on an exe without them -> no line.
- Values: "on", "off", "on + boost" (Reflex), "unavailable: <reason>", "off: restart the game to apply", "on: off after a game restart", "not active: needs vid_restart, else see the log".
- DLSS reasons in order: not NVIDIA (HW.Caps.id_vendor), nvngx_dlss.dll missing next to the exe, no SSS motion vectors (`o.ssfx_motionvectors`), HDR10 (`o.dx11_hdr10`), `Dlss.init_failed()` (r4_dlss.h getter = NGX init ran and failed), MSAA (only when r4_dlss is set: `o.dx10_msaa` is fixed at device creation, DLSS forces it off only from the next start).
- FG reasons: from `DX12Present_FrameGenWantsInputs()` (FG swapchain running) / `DX12Present_FrameGenTried()` (bridge .cpp, set in DX12Present_Create), HDR10, no SSS vectors, MSAA, FSR DLLs missing, bridge cvar off. Reflex: not NVIDIA or `Reflex::Failed()` (dxReflex).
- Strings: `gamedata\configs\text\eng\ui_mm_dlss.xml` (option name `ui_mm_video_advanced_<id>`, hint `..._desc`, list values `ui_mm_lst_<key>`); English only.
- Test archive: `C:\Anomaly\db\mods\01_dlss_b_test.db0` = the script + text XML + `shaders\r3\upscale_sharpen.ps`, packed from a scratch copy with xrCompress (`-ltx build_patch.ltx -pack -strong -1024 -db`).
- Gotcha: the startup console dump ("Console variables" in the log) runs before the render device, when `HW.Caps.id_vendor` is still 0; status there used to read "unavailable: not an NVIDIA GPU" on an RTX card (the false Reflex report).
