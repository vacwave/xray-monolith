# DX12 presentation bridge (D7, `r4_dx12_present`)
- Cvar `r4_dx12_present` 0/1 (xrRender_console.cpp), read in `CHW::CreateDevice` only (vid_restart = `CHW::Reset`, does not re-read it). Off = the old `CreateSwapChainForHwnd(pDevice, ...)` line, nothing else changed.
- Shape: `DX12Present_Create` (Layers/xrRenderDX10/dx12PresentBridge.cpp) returns an `IDXGISwapChain1` proxy that sits in `HW.m_pSwapChain`; every engine call site (Reset/ResizeBuffers/SetFullscreenState/Present/GetBuffer, r4 `RenderToTarget`, xr_effgamma `GetContainingOutput`) stays unchanged.
- Proxy `GetBuffer(any)` = the D3D11 view of a D3D12 committed texture (`HEAP_FLAG_SHARED`, swapchain format, `ALLOW_RENDER_TARGET`, opened with `OpenSharedResource1`) → pBaseRT, screenshots and the SVP copy all read it.
- Sync = one D3D12 fence (`FENCE_FLAG_SHARED`, opened on D3D11 via `ID3D11Device5::OpenSharedFence`), one monotonic counter: D3D11 Signal+Flush → D3D12 queue Wait → copy (back buffer PRESENT→COPY_DEST barrier, shared texture implicit COMMON→COPY_SOURCE) → D3D12 Signal → D3D11 `ID3D11DeviceContext4::Wait` → D3D12 Present. Every Signal is ordered behind a Wait on the other device's last value, so the fence never goes backwards.
- CPU pacing: 3 command allocators, each waits (10 s timeout, logs) for its last fence value; D3D11 has no Present any more, so this is what bounds frames in flight.
- `ResizeBuffers` / `SetFullscreenState` / destruction: WaitIdle (both devices) → release shared texture + back buffer refs → forward → recreate. `Present(DXGI_PRESENT_TEST)` is not forwarded: it returns both devices' removed reasons mapped to DEVICE_REMOVED / DEVICE_RESET (the only codes `GetDeviceState` handles).
- `QueryInterface` for IDXGISwapChain2/3/4 returns the real D3D12 swapchain (CreateDevice's `SetColorSpace1` goes there). D8: replace the `CreateSwapChainForHwnd(m_queue, ...)` in `Init` with the FSR FG swapchain on the same queue; buffers come from `GetBuffer` the same way.
- D3D12 device is created on the adapter of the D3D11 device (LUID via IDXGIDevice → `EnumAdapterByLuid`); `-dxgi_dbg` also enables the D3D12 debug layer. Links `d3d12.lib` via `#pragma comment`.
- Limits: HDR10 (`r4_hdr10_on 1`) → bridge off with a log line (shared texture + HDR colour space not designed). Exclusive fullscreen is refused (coordinator decision, D8): `rs_screenmode fullscreen` becomes borderless in `CHW::CreateDevice`/`Reset` (`dx12_force_borderless`, log line), the proxy `SetFullscreenState(TRUE)` forwards FALSE with a log line. Needs Windows 10 1703+ (Device5) else falls back with a `! r4_dx12_present` line. ReShade/overlays hooking the D3D11 swapchain will not see the bridge's D3D12 one.
- Testing: the cvar can't be toggled live; launch with `-ltx <abs path>.ltx` (≤63 chars, no spaces; `CCC_LoadCFG` takes an absolute name as is) holding the template + `r4_dx12_present 1`.
- Testing gotcha: a bare `-ltx name.ltx` is looked up in the MCP slot's `-appdata`, not next to the exe; check the log for `! Cannot open script file` (then nothing of the ltx applied, not even `renderer`). `C:\Anomaly\bin_dlss_b\fgdlss_hud.ltx` = fgdlss.ltx without `hud_draw off`.
- Test 2026-11-18 (vanilla 1080p, uncapped, 5 s still): ON avg 1.82 / p99 5.43 ms vs OFF 2.20 / 5.82 ms (one sample each, copy+sync cost below noise); vsync on caps at 240 Hz; vid_mode 720p<->1080p x5 resets fine; GAMMA launch OK. Pre-existing (bridge OFF too): silent run + s_screenmode windowed -> FATAL R_CHK in `CHW::UpdateViews` depth CreateTexture2D (E_INVALIDARG).
- Pre-existing `rs_screenmode windowed` crash in `CHW::UpdateViews`: windowed mode sizes the swapchain from `GetClientRect` (`CHW::selectResolution`, g_screenmode 0), a minimized/hidden MCP window gives 0x0 -> depth `CreateTexture2D` E_INVALIDARG. Not fixed.

## FSR frame generation swapchain (D8 phase 1, `r4_framegen`)
- Cvar `r4_framegen` 0/1 (xrRender_console.cpp), read in `CHW::CreateDevice` only, passed as `framegen` to `DX12Present_Create`. Without the bridge (cvar off, HDR10, bridge failure) -> `! r4_framegen: needs the DX12 presentation bridge ...` and off.
- `CFrameGen` (Layers/xrRenderDX10/dx12FrameGen.*) wraps the FSR API: `LoadLibrary("amd_fidelityfx_loader_dx12.dll")` + GetProcAddress (no import lib, never unloaded: the proxy swapchain code lives in the DLLs), swapchain context `..._FOR_HWND_DX12` on the bridge queue (replaces the plain `CreateSwapChainForHwnd`), FG context (display size = max render size = swapchain size, back-buffer format, flags 0).
- Any failure (DLL missing, swapchain or context creation, shared textures) -> everything FG released, plain bridge swapchain, `! r4_framegen: frame generation off, using the plain DX12 swapchain` after the reason line.
- Order: destroy = WaitForPresents -> WaitIdle -> FG context (Configure disabled, then destroy) -> buffer refs -> swapchain context -> last COM ref. ResizeBuffers rebuilds the FG context around the resize (display size). SDK: one swapchain per HWND, so the FG one must be gone before the plain fallback is created.
- FG mode moves the D3D12->D3D11 fence release (`ReleaseToD3D11`) after the swapchain Present: interpolation (frameGenerationCallback, allowAsyncWorkloads false) runs inside Present on the bridge queue and reads the shared textures. Plain mode keeps the D7 order.
- HUD-less colour: second shared texture `m_hudless12/11` (same desc as the back buffer, FG mode only); `DX12Present_CaptureHudless()` (dx12PresentBridge.h) copies the back buffer into it on D3D11, skipped on SVP frames; `Present` passes it to `CFrameGen::OnPresent` only if captured this frame.
- HUD-less hook (Dev A file, not applied in phase 1): r4_R_render.cpp `CRender::Render`, right after `Target->phase_combine();` (:347): `DX12Present_CaptureHudless();` + `#include "../xrRenderDX10/dx12PresentBridge.h"`. There the back buffer holds scene + HUD weapon + post chain (phase_pp or the !PP_Complex combine), before `CLevel::OnRender` draws reshade effects and `HUD().RenderUI()` (Level.cpp:1354-1357); render_forward draws into rt_Generic_0 pre-post, so capturing there would flag every post effect as UI.
- FSR FG swapchain `GetContainingOutput` returns no output (S_OK + null): `CGammaControl::Update` (xr_effgamma.cpp:15) dereferenced it and crashed at startup; the proxy now falls back to `WindowOutput` (D3D11 adapter output showing the window, else output 0).
- MCP silent runs already turn `rs_screenmode fullscreen` into borderless (`CCC_Screenmode`, xr_ioc_cmd.cpp:626), so the bridge's borderless log line can't be seen there; it only shows in a visible launch.
## Interpolation (D8 phase 2)
- Hooks in `CRender::Render` (r4_R_render.cpp, right after `Target->phase_combine()`): `DX12Present_CaptureHudless(); DX12Present_SetFrameGenInputs();`. `DX12Present_SetFrameGenInputs` (bridge .cpp, R4 only, reads `RImplementation.Target`) copies `rt_dlss_depth` + `rt_dlss_mv` on D3D11 into render-size textures shared with D3D12 (R32F / RG16F, `CreateShared` with ALLOW_RENDER_TARGET | ALLOW_SIMULTANEOUS_ACCESS: without simultaneous access D3D11 `OpenSharedResource1` fails E_INVALIDARG for these formats on the 2080 Super, RGBA8/RGBA16F open with RT alone; same fence as the back buffer; recreated after WaitForPresents + WaitIdle when the render size changes) and fills `FrameGenInputs`.
- Temporal inputs on for FG: `begin_temporal_frame` ORs `DX12Present_FrameGenWantsInputs()` into `want`; FG alone (no upscaler, no `r4_upscale_debug`) zeroes `jitter_px` unless SSS TAA runs (`ps_ssfx_taa.x > 0 && o.ssfx_taa`), else the frame would shake with nothing to resolve the jitter.
- Conventions passed to prepare: motionVectorScale (1,1) (`rt_dlss_mv` = prev − cur in render pixels = FSR's direction), jitter = `jitter_px` as is (FSR's jitter maps to clip (2jx/w, −2jy/h), the same as the `ssfx_jitter` binder), no create flags (depth not inverted, not infinite, render-res vectors, no jitter in vectors). near = −_43/_33, far = _43/(1−_33), fovY = 2·atan(1/_22) from `Device.mProject` (the matrix `upscale_inputs` used); viewSpaceToMeters 1; camera vectors from `Device.vCamera*`; frame time = QPC between input frames (fTimeDelta follows the time factor).
- Per present (`CFrameGen::OnPresent`): inputs valid + HUD-less captured this frame → `Configure(true, hudless)` then `ffxDispatchDescFrameGenerationPrepareV2` into the open bridge list (same frameID, +1 per present); else Configure(false) once (hold). Provider without V2 (UNKNOWN_DESCTYPE / NO_PROVIDER / NO_SUPPORT_NEW_DESCTYPE) → deprecated prepare + camera info, logged once. `history_reset` → prepare `reset` and the dispatch callback's `params->reset` (callback runs inside Present, allowAsyncWorkloads false).
- Hold cases (no SetInputs that frame): main menu active (`g_pGamePersistent->m_pMainMenu->IsActive()`), loading screen / menu-only frames (no `CRender::Render`), `temporal_active` false. SVP frames are never presented; with a 3D scope every main frame has `history_reset` (frame gap), so interpolation runs in reset mode while aiming.
- No vectors (vanilla without SSS, or MSAA): `! r4_framegen: interpolation unavailable (...)` once (plus D2's `! temporal upscaler inputs unavailable` line), FG stays pass-through.
- Log: `* r4_framegen: interpolation on` / `held (...)` on state changes; every 10 s while interpolating AND `r4_upscale_debug` != 0 (toggle it live for ~12 s, it also shows the debug view) `* r4_framegen: 10.0 s: N rendered (fps), M with interpolation, G generated -> fps presented` (G counted in the frameGenerationCallback; game_perf / engine timers see rendered frames only). GPU memory of the FG context + swapchain logged at context creation; shared inputs = 8 B/render pixel (~16 MB at 1080p).
- Pacing: `r__framelimit` caps rendered frames (the busy-wait in device.cpp runs before Present); the FG swapchain presents rendered + generated, so cap 30 → ~60 presented. FSR wants 60+ rendered fps for good quality.
- Test 2026-11-18 (AnomalyMO2 with SSS, l01_escape, 1080p): rendered 47.8 / presented 95.7 fps (game_perf sees rendered only), menu + save/load -> held then on, r4_render_scale 0.67 inputs 1286x724 148 -> 296 fps, vid_mode 720p<->1080p rebuilds context + inputs, cap 30 -> 30 rendered / 60 presented; GAMMA: 151 -> 302 fps, 5.3 of 8 GB VRAM, FG context 147.6 MB + swapchain 33.8 MB; exit 0. Interpolated frames NOT checked visually (MCP screenshots read the DX11 back buffer = rendered frames); SVD aim in GAMMA logged no held/reset (scope path not proven exercised).
- SDK notes: FG swapchain header is 4.0.0 (RX 9000 only); on other GPUs the runtime falls back to swapchain 3.1.7 / FG 3.1.6 (provider name is logged). Disabling FG via Configure waits for presents (SDK doc), so phase 1 configures only once.
- Stats line `10.0 s: N rendered ...` only prints while `r4_upscale_debug != 0` (D11); state-change lines always.
- Testing: `C:\Anomaly\bin_dlss_b\fgon.ltx` (= dx12on.ltx + `r4_framegen 1` + `rs_screenmode fullscreen` to exercise the borderless force), `fgnobr.ltx` (= dx12off.ltx + `r4_framegen 1`). Deploy also needs `amd_fidelityfx_loader_dx12.dll` + `amd_fidelityfx_framegeneration_dx12.dll` from `sdk\binaries\FidelityFX\` next to the exe.
- Test 2026-11-18 (vanilla fake_start, 1080p, uncapped, 5 s still, one sample each): FG swapchain pass-through 701 fps avg 1.43 / p99 2.67 ms (present 0.70) vs plain bridge 819 fps 1.22 / 2.46 ms (present 0.54): the swapchain's extra copy + threads cost ~0.2 ms. Providers on the 2080 Super: swapchain 3.1.7, FG 3.1.6. vid_mode 720p<->1080p rebuilds the FG context; quit exit code 0 for bridge and FG swapchain.

## UI texture for frame generation (D12)
- With the FG swapchain the 2D UI goes into its own target instead of the HUD-less guess. Hooks: `Render->BeginUI()` (new default-empty `IRender_interface` virtual, R4 -> `DX12Present_BeginUI`) in `CLevel::OnRender` right before `HUD().RenderUI()`; `DX12Present_EndUI()` in `dxRenderDeviceRender::End` after `RCache.OnFrameEnd`, before `DoAsyncScreenshot`. Both no-ops without FG / on SVP frames.
- UI target = everything drawn from BeginUI to the frame end: HUD UI, inventory/PDA/dialogs, console, cursor, stats, imgui, MCP nav and script debug draws. Stays on the frame: scene, HUD weapon, post chain, bullet tracers, reshade effects (all drawn before). Esc main menu and loading screens never call BeginUI (level removed from seqRender) -> whole image is "scene", FG is held there anyway.
- Redirect = `HW.pBaseRT` swapped to the UI target's RTV between BeginUI and EndUI, so every `set_RT(HW.pBaseRT)` (e.g. `EndUI3DIconAtlas`) lands there too; restored in EndUI.
- UI target RGBA16F holds (colour, transmittance T), cleared (0,0,0,1); frame = colour + T * frame. Blend modes: `dx10StateManager::Apply` remaps the alpha factors while RT0 is the UI target (`SetUiTarget`, `UiBlendState`): src alpha factor ZERO (DEST_ALPHA if the colour src factor is DEST_COLOR), dest alpha factor follows the colour dest factor (INV_SRC_* -> INV_SRC_ALPHA, SRC_* -> SRC_ALPHA, ZERO -> ZERO, else ONE); blend-off draws become (ONE, ZERO) colour + T = 0. Exact for SET / BLEND / ADD / ALPHA-ADD (`Blender_Screen_SET` modes, `hud_default.s`), MUL / MUL_2X approximate the per-channel multiply with source alpha. Draws into other targets during the UI (3D icon atlas) are not remapped. imgui sets its own blend state (premultiplied alpha, not transmittance): imgui overlays composite slightly wrong.
- EndUI: copy back buffer -> `m_hudless11` (= frame without UI), one MRT fullscreen pass (runtime `D3DCompile`, raw D3D11, context cleared after): RT0 back buffer blend (ONE, SRC_ALPHA) = frame + UI as before (screenshots / SVP see it), RT1 shared `m_ui11/12` = (colour, 1 - T) premultiplied for FSR.
- Present: frames with UI composited and FG inputs valid copy `m_hudless12` (UI-less) to the swapchain and register `m_ui12` every present (`ffxConfigureDescFrameGenerationSwapChainRegisterUiResourceDX12` on the swapchain context, flags USE_PREMUL_ALPHA + ENABLE_INTERNAL_UI_DOUBLE_BUFFERING, state COMMON); FG configured without HUDLessColor. Held frames copy the composited back buffer and unregister (null resource). Relies on the swapchain compositing the UI onto rendered frames too (SDK header only says "generated frames"; no doc in the repo): unverifiable with MCP screenshots, user check.
- Fallback to HUD-less mode for the session (one `!` line): composite shader / textures not created, or the provider refuses the registration. Resize: `ReleaseBuffers` unregisters + releases, `CreateBuffers` recreates (log `* r4_framegen: UI texture WxH`). Cost: +16 MB (RGBA16F) + 8 MB shared at 1080p, one fullscreen pass; the phase_combine HUD-less copy is skipped in UI mode.
- Test 2026-11-19 (AnomalyMO2, l01_escape 1080p, provider swapchain 3.1.7 / FG 3.1.6): log `UI texture registered`, interpolation on, ~96 rendered -> ~193 presented fps; inventory, Esc menu, console, dialog screenshots on vs off (plain DX11) look the same; vid_mode 720p<->1080p rebuilds the UI texture + context; exit 0 both runs; vanilla (no SSS, FG pass-through, UI composite still runs) HUD + PDA on vs off look the same. Generated-frame UI quality NOT checked (MCP screenshots = rendered frames).

## NVIDIA Reflex (D11, `r4_reflex`)
- Cvar `r4_reflex` 0 off / 1 low latency / 2 + boost (xrRender_console.cpp), runtime. Code: `Layers/xrRenderDX10/dxReflex.*` (R4 only, namespace `Reflex`), reached from the engine through two default-empty `IRenderDeviceRender` virtuals (`LatencyFrameStart(cap)`, `LatencySimulationEnd()`, implemented in dxRenderDeviceRender under USE_DX11). Off and never on = no NvAPI call at all (old frame loop).
- Sleep site: `CRenderDevice::on_idle` (device.cpp) right after `mcp_perf::frame_begin()`, on the main thread, before `seqParallelBeforRender` and `FrameMove` (input = `CInput::OnFrame` in seqFrame, REG_PRIORITY_HIGH). The main thread owns the frame: GameThread / PreRender tasks are launched later in on_idle and joined at its end (`secondary_tasks.wait()`), so nothing of the next frame runs before the sleep. Loading-screen frames (early return) skip it (driver falls back after a few frames, by design).
- Markers (cheap, main thread only): SIMULATION_START after Sleep, SIMULATION_END after FrameMove, RENDERSUBMIT_START in `dxRenderDeviceRender::Begin`, RENDERSUBMIT_END + PRESENT_START/END around the swapchain Present in `End` (only for frames whose Sleep ran; SVP frames have no present markers). frameID +1 per Sleep. `bUseMarkersToOptimize` stays false.
- Limiter: with `r__framelimit` N and Reflex on, `minimumIntervalUs = 1e6/N` and the ECO_RENDER busy-wait in on_idle is skipped (`LatencyFrameStart` returns true); framelimit 0 keeps the engine's menu/pause refresh-rate cap. SetSleepMode is re-sent only when mode, cap or device change (log line `* r4_reflex: low latency on[ + boost], <D3D11|D3D12 (bridge)> device, frame cap <N fps by Reflex|none>` / `* r4_reflex: off`).
- Device: the presenting one: `DX12Present_Device()` (bridge D3D12 device) when the bridge is up, else `HW.pDevice`. Reflex keys on the device's presents; with the bridge D3D11 never presents.
- Unsupported: NvAPI_Initialize / SetSleepMode / Sleep failure -> `! r4_reflex: <call> failed (status, text), Reflex off`, off for the session (no retry on re-toggle).
- Bridge + FG limits: the sleep/markers cover the engine frame up to the proxy `Present`; the D3D11->D3D12 fence wait, copy, FSR interpolation and the generated frame's present (FSR's own present thread) are outside the markers, and the driver sees 2 presents per rendered frame. Measured: cap 30 still gives 30 rendered / 60 presented (no halving), but no frame-time gain and the real latency benefit there is unmeasured.
- Test 2026-11-19 (AnomalyMO2 vanilla+SSS, l01_escape 1080p, not noisy): DX11 uncapped 0/1/2 = 194.6/192.6/184.0 fps, avg 5.14/5.19/5.43, p99 6.9/9.5/9.9 ms (sleep moves into `before_frame` ~2.5 ms, present 0.05 ms). Cap 30 steady: 30.0 fps all modes, p99 34.5 (off) vs ~40 ms (Reflex), max 41; cap 60: 60.0 fps, p99 17.3 vs 22.2. Switching mode with a cap gives one 90-130 ms hitch (SetSleepMode), none in steady state. Bridge+FG uncapped 118 fps rendered / 236 presented in all modes; toggles x3 fine; exit 0 both runs.
- D9 soak 2026-11-19 (GAMMA, user's config 3840x2160 borderless + bridge + FG + DLSS quality default 2560x1440 + sharpness 0.5 + Reflex 1, uncapped, ~11 min one session): Cordon walk/fights, inventory/PDA/dialogue, ACOG/Kobra/PKA aim+strafe, rain, night, emission, save+load, l02_garbage and back, 2 vid_restarts, options menu: 0 `!` lines for dlss/ngx/framegen/reflex/dx12/temporal/upscale/shader, no `DLSS output is empty`, no crash/hang, exit 0. game_perf (still, clear day): 35.8 fps rendered, avg 27.9 / p99 38.7 ms (present phase 18.4 ms = GPU bound at 4K); FG stats 40.9 rendered -> 81.8 presented fps (409/409 interpolated); FG context 434 MB + swapchain 128 MB + inputs 28 MB VRAM.
