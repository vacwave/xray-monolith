# Render / screenshots
- `screenshot` cmd = `CCC_Screenshot` Layers/xrRender/xrRender_console.cpp:731 → `Render->Screenshot()`.
- API xrEngine/Render.h:445-448: `Screenshot(mode,name)`, `Screenshot(mode,CMemoryWriter&)` (SM_FOR_MPSENDING only, small DDS, r__screenshot.cpp:419), `ScreenshotAsyncBegin/End(CMemoryWriter&)` → w,h + raw RGBA (:437-555); used by xrGame/screenshot_manager.cpp:201,252.
- Normal mode encodes JPG/PNG/BMP in memory via `D3DX11SaveTextureToMemory` :176 before writing.
- MCP screenshots (`xrEngine/mcp_screenshot.{h,cpp}`, registered in `mcp::start`): `screenshot.begin {max_width,format,quality,save_path}` -> `{id,frame}` calls `Render->ScreenshotAsyncBegin()`; `screenshot.get {id}` -> `{"pending":true,"stage":"frame"|"encode"}` or the result. Request+poll (no deferred-reply facility in mcp_server).
- Capture = async path: `dxRenderDeviceRender::End` -> `DoAsyncScreenshot` copies the back buffer (3D + HUD/UI, before Present) into the staging `t_ss_async` on the frame rendered right after the request (seqFrame precedes render in on_idle); `screenshot.get` reads it back once `Device.dwRenderedFrames` moved (Map + BGRX convert ~5-13 ms main thread at 1080p).
- Fixed: R4 `CRenderTarget::DoAsyncScreenshot` used `GetBuffer(0, __uuidof(ID3D10Texture2D))`, which fails on DX11 -> copied nothing (black, and MP screenshot_manager never worked on DX11); now `HW.pBaseRT->GetResource` + release.
- Fixed: DX10/11 `ScreenshotAsyncEnd` ignored RowPitch and wrote into the READ-mapped memory; now converts row by row into the writer; writes nothing on HDR10 (R10G10B10A2 back buffer can't be copied into the 8-bit staging) or Map failure -> `screenshot.get` error.
- t_ss_async is R8G8B8A8_SNORM staging; CopyResource from the R8G8B8A8_UNORM back buffer keeps raw bytes. Output bytes BGRX = WIC GUID_WICPixelFormat32bppBGR; rows top-down, no gamma change (colours/orientation verified).
- Encoding: WIC (windowscodecs, OS component, `#pragma comment`) on a detached worker thread with its own MTA COM init (no COM on the main thread): Fant downscale to max_width, JPEG (ImageQuality) or PNG via 24bppBGR converter, base64 inline in the JSON result; full-res save_path written by the engine (.jpg/.jpeg q95 else PNG). Decided over D3DX (no JPEG quality, no scaling) and Python (no Pillow).
- Sizes/timings at 1920x1080: default 1024x576 JPEG q70 ~35-60 KB; PNG 800 px ~400 KB; full-res PNG 1.6 MB (~100 ms, worker); a shot ~80-110 ms round trip (3 frames at the 30 fps cap); 20 in a row: no memory growth.
- Metadata frame/level are taken at request time: a request just before a level load is read back after it (seen 4 s later), and may even show the loading screen (End() also runs in LoadDraw).
- Loading screen is not reliably capturable (main thread blocked, requests not drained): the supervisor refuses while `engine.heartbeat.loading`, else a blocked get times out with a clean error.
