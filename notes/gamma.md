# GAMMA (MO2) launching and differences
- `C:\GAMMA` is only the MO2 folder (no fsgame.ltx, no bin): MO2 `gamePath` = `C:\Anomaly`; mods are loose dirs `C:\GAMMA\mods\<name>\gamedata` overlaid by usvfs into `C:\Anomaly`; profile `G.A.M.M.A` (modlist.txt), overwrite `C:\GAMMA\overwrite`. game_launch(game_root=C:\GAMMA) fails "no fsgame.ltx".
- Working launch (goal 23, manual): `C:\GAMMA\ModOrganizer.exe -p "G.A.M.M.A" run "C:\Anomaly\bin\AnomalyDX11AVX.exe" -a "-fsltx C:\Anomaly\fsgame.ltx -appdata <dir> -mcp_port 0"` -> game is MO2's child (pid via Win32_Process ParentProcessId), silent; then game_attach(appdata=<dir>). Copy mcp/templates/user.ltx into <dir> first.
- Killing our own MO2 right after the game child appears (~3.3 s) is reliable (3/3): port after ~30 s, new game ~31 s, mod files still resolve, graceful quit. usvfs lives in the game process; no usvfs_proxy helper seen.
- Gotcha: starting another MO2 `run` while a GAMMA game is still in startup (OnAppStart; the MCP port is up before it ends) crashed that game: once usvfs __fastfail (WER dump), once FATAL "can't open file character_dialogs.xml" (usvfs rebuilt its shared tree). A game already in a level survived a second launch. Serialize GAMMA launches until the previous one reached the main menu.
- Writes under MO2: -appdata dir gets logs/saves/shaders_cache/user.ltx; options/new-game config goes into the GAMMA mod file `G.A.M.M.A. MCM values ...\gamedata\configs\axr_options.ltx`; MO2 rewrites its profile files (same content) and ModOrganizer.ini UI state on start/exit.
- GAMMA mutes do not stick: `zzz_player_injuries` sets `snd_volume_eff` from MCM `sound/general/master_volume` on every actor_on_first_update; re-run `snd_volume_eff 0` after each load (game_teleport cvars).
- Differences: first new game load ~31-39 s (vanilla ~12-13 s), later level loads 13-16 s; 8 non-fatal script load errors from the mod list itself (a_faction_prices, mags_patches, zz_ui_inventory_better_stats_bars, zzz_mspizza_godis_zoomcalc); stalker kit 29 items / 5000 RU without a pistol; Fanatic's task is esc_2_12_stalker_fanat_task_3 (clear mutants in y04_pole).
- `Reload Unjam Same Key Fix` mod keeps wpn_reload on kR; injected `reload` fires `on_before_key_press`/`on_key_press` (dik 19, bind 34) and refills the mag, same as vanilla.
