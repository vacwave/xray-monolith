# Perf measurement (game_perf, perf.* methods)
- Engine: `src/xrEngine/mcp_perf.{h,cpp}` (namespace `mcp_perf`), registered from `mcp::start` (`register_methods`); xrGame side `src/xrGame/mcp_perf.cpp` (`mcp_register_perf()` in `CGamePersistent::OnAppStart`) supplies the Lua heap reader and the luabind hook switch.
- Methods: `perf.start {"seconds":S}` (0.1..120, default 5; restarts a running window) → `{"started","seconds"}`; `perf.report` → `{"running":true,"elapsed_seconds","frames","seconds"}` while open, then the report; error before any window. Supervisor `game_perf(instance, seconds)` = start, sleep S, poll report every 0.2 s (gives up after S+30 s).
- Window opens at the first `frame_begin` after perf.start and closes at the first frame begin (or loading frame) after S s; the frame in which perf.start ran is not counted. Loading frames (`g_loading_events`) are not frames (`loading_breaks` counts interrupted frames).
- Frame = time between successive `frame_begin` calls (on_idle after the loading early-out), so it includes the message pump ("other").
- Decided: hitch = frame > max(2 × p50, 33.3 ms). Percentiles are nearest-rank over all frames of the window.
- Main-thread phases (device.cpp on_idle marks, each = time since the previous mark): before_frame (seqParallelBeforRender), frame_move (FrameMove: seqFrame), pre_render (particles, matrices, task submit, bones if not MT), limiter (ECO_RENDER busy-wait), render (seqRender + stats; also Begin/epilogue), present (End(): Present = GPU/vsync wait), wait_tasks (secondary_tasks.wait: GameThread, LuaGC, particles, bones), inactive_sleep (Sleep(1) when !b_is_Active), other = frame − sum. Phases always sum to the frame.
- Each phase also reports lua_ms (main-thread Lua + explicit GC inside it). `main.scheduler_rt` (section inside frame_move) = `Sheduler.UpdateInit/UpdateRT` (or full `Update` when !mt_Scheduler) in `CGamePersistent::OnFrame`: actor/binder updates incl. `actor_on_update` callbacks run there.
- Frame limiter (device.cpp ECO_RENDER) is a busy-wait on the main thread after the GameThread submit; it is active when `r__framelimit` > 0, OR in the main menu / paused (then capped to the monitor refresh, `refresh_rate` = 1/Hz). `main.busy_ms` = frame − limiter − inactive_sleep; `cap.capped` = limiter > 5 % of frame or vsync (`rs_v_sync`, waits inside Present, cannot be split out).
- Lua timing choke points: `luabind::detail::pcall` and `resume_impl` (pcall.cpp; every luabind functor/object/call_member call and script-thread resume; `CScriptThread::update` now resumes via `resume_impl`) through `luabind::detail::pcall_hook` (null unless a window is active); explicit GC steps via `mcp_perf::gc_scope` in `CLevel::script_gc` (main, LUA_GCSTEP) and `CLevel::LuaGC` (parallel GC task).
- Only the outermost Lua entry per thread is timed (tls depth); nested C++→Lua calls are inside it. Entries count = outermost entries per frame.
- Main vs worker Lua: worker = inside a `task_scope` (GameThread, deferred scheduler) or not the main thread (PPL may run GameThread inline on the main thread in wait(); that time is in wait_tasks and its Lua counts as worker).
- Not covered: raw `lua_pcall`/`lua_call` outside luabind (script loading/do_file, `run_string` without a level, `lua.exec` itself, luasocket/marshal internals), LuaJIT FFI callbacks, and implicit GC on allocation (counted inside the Lua call that allocated).
- Memory: working set/peak/private (K32GetProcessMemoryInfo, at report time); Lua heap MB start/end/min/max sampled at every frame begin (`lua_gc` COUNT/COUNTB, main thread, no worker Lua then); `lua_growth_kb_per_frame` = sum of positive frame-to-frame heap deltas / frames (lower bound: GC in the same frame hides allocation); `engine_alloc_calls_per_frame` = `Memory.stat_calls` delta (non-atomic counter, approximate). VRAM not reported (needs render-layer DXGI access).
- Not reused: `Device.Statistic` CStatTimers (gated by rs_stats, smoothed, no limiter/Lua split) and Optick (`PROF_EVENT`, only with a profiler attached).
- Cost with no window: one bool test per mark/scope and one null-pointer test per luabind pcall. Active: 2 QPC per outermost Lua entry, per GC step and per mark.
- Gotcha: with parallel GC (`lua_parallel_gc`, default on) the main thread does no explicit GC (`main.gc_ms` 0); the GC task loops up to `psLua_ParallelGC_CallAmount` (25) steps while `Device.isRendering`, so `tasks.gc_ms` grows with the limiter wait (~6 ms at 30 fps cap) and is not main-thread load; the last step shows up in wait_tasks.
- With `lua_parallel_gc 0` the LUA_GCSTEP(300) in `CLevel::script_gc` runs once per frame on seqParallel (worker) when the `mt_config` mtLUA_GC flag is set (default), so it still shows under `tasks.gc_ms` (gc_steps 1.0) and inside game_thread_ms; `main.gc_ms` only moves when mtLUA_GC is off.
- Overhead measured: no-window FPS new vs pre-change exe within noise (≈1475-1500 vs ≈1490-1505 fps, interleaved runs); window active vs no window in the same session ≈1394 vs 1396 fps.
- Measured (fake_start, uncapped, noisy shared machine): baseline ≈1.3 ms frame, Lua 0.24 ms (≈15 outermost entries/frame, mostly scheduler_rt); a 10 ms busy `actor_on_update` callback → Lua 11.5 ms, frame 14.3 ms; 20k-table garbage per update → Lua 11.2 ms, heap growth ≈890 KB/frame; both back to baseline after removal. 30 fps cap: limiter 32 ms, busy 1.8 ms.
- Goal 10 hooks: per-function profiling can hang off `luabind::detail::pcall_hook` (all luabind entries; add the called function's identity there) plus `lua_sethook` while a window is active; phase/section enums in mcp_perf.h are the place for new main-thread sections.
