# Perf measurement (game_perf, perf.* methods)
- Engine: `src/xrEngine/mcp_perf.{h,cpp}` (namespace `mcp_perf`), registered from `mcp::start` (`register_methods`); xrGame side `src/xrGame/mcp_perf.cpp` (`mcp_register_perf()` in `CGamePersistent::OnAppStart`) supplies the Lua heap reader and the luabind hook switch.
- Methods: `perf.start {"seconds":S}` (0.1..120, default 5; restarts a running window) → `{"started","seconds"}`; `perf.report` → `{"running":true,"elapsed_seconds","frames","seconds"}` while open, then the report; error before any window. Supervisor `game_perf(instance, seconds)` = start, sleep S, poll report every 0.2 s (gives up after S+30 s).
- Window opens at the first `frame_begin` after perf.start and closes at the first frame begin (or loading frame) after S s; the frame in which perf.start ran is not counted. Loading frames (`g_loading_events`) are not frames (`loading_breaks` counts interrupted frames).
- Frame = time between successive `frame_begin` calls (on_idle after the loading early-out), so it includes the message pump ("other").
- Decided: hitch = frame > max(2 × p50, 33.3 ms). Percentiles are nearest-rank over all frames of the window.
- Main-thread phases (device.cpp on_idle marks, each = time since the previous mark): before_frame (seqParallelBeforRender), frame_move (FrameMove: seqFrame), pre_render (particles, matrices, task submit, bones if not MT), limiter (ECO_RENDER busy-wait), render (seqRender + stats; also Begin/epilogue), present (End(): Present = GPU/vsync wait), wait_tasks (secondary_tasks.wait: GameThread, LuaGC, particles, bones), inactive_sleep (Sleep(1) when !b_is_Active), other = frame − sum. Phases always sum to the frame.
- Each phase also reports lua_ms (main-thread Lua + explicit GC inside it). `main.scheduler_rt` (section inside frame_move) = `Sheduler.UpdateInit/UpdateRT` (or full `Update` when !mt_Scheduler) in `CGamePersistent::OnFrame`: actor/binder updates incl. `actor_on_update` callbacks run there.
- Frame limiter (device.cpp ECO_RENDER) is a busy-wait on the main thread after the GameThread submit; it is active when `r__framelimit` > 0, OR in the main menu / paused (then capped to the monitor refresh, `refresh_rate` = 1/Hz). `main.busy_ms` = frame − limiter − inactive_sleep; `cap.capped` = limiter > 5 % of frame or vsync (`rs_v_sync`, waits inside Present, cannot be split out).
- Lua timing choke points: `luabind::detail::pcall` and `resume_impl` (pcall.cpp; every luabind functor/object/call_member call and script-thread resume; `CScriptThread::update` now resumes via `resume_impl`) through `luabind::detail::pcall_hook` (null unless a window is active); explicit GC steps via `mcp_perf::gc_scope` in `CLevel::script_gc` (main, LUA_GCSTEP) and `CLevel::LuaGC` (parallel GC task).
- Only the outermost Lua entry per thread is timed (tls depth); nested C++→Lua calls are inside it. Entries count = outermost entries per frame.
- Main vs worker Lua: worker = inside a `task_scope` (GameThread, deferred scheduler) or not the main thread (PPL may run GameThread inline on the main thread in wait(); that time is in wait_tasks and its Lua counts as worker).
- Not covered: raw `lua_pcall`/`lua_call` outside luabind (script loading/do_file, `run_string` without a level, `lua.exec` itself, luasocket/marshal internals), LuaJIT FFI callbacks, and implicit GC on allocation (counted inside the Lua call that allocated).
- Memory: working set/peak/private (K32GetProcessMemoryInfo, at report time); Lua heap MB start/end/min/max sampled at every frame begin (`lua_gc` COUNT/COUNTB, main thread, no worker Lua then); `lua_growth_kb_per_frame` = sum of positive frame-to-frame heap deltas / frames (lower bound: GC in the same frame hides allocation); `engine_alloc_calls_per_frame` = `Memory.stat_calls` delta (non-atomic counter, approximate). VRAM not reported (needs render-layer DXGI access).
- Not reused: `Device.Statistic` CStatTimers (gated by rs_stats, smoothed, no limiter/Lua split) and Optick (`PROF_EVENT`, only with a profiler attached).
- Cost with no window: one bool test per mark/scope and one null-pointer test per luabind pcall. Active: 2 QPC per outermost Lua entry, per GC step and per mark.
- Gotcha: with parallel GC (`lua_parallel_gc`, default on) the main thread does no explicit GC (`main.gc_ms` 0); the GC task loops up to `psLua_ParallelGC_CallAmount` (25) steps while `Device.isRendering`, so `tasks.gc_ms` grows with the limiter wait (~6 ms at 30 fps cap) and is not main-thread load; the last step shows up in wait_tasks.
- With `lua_parallel_gc 0` the LUA_GCSTEP(300) in `CLevel::script_gc` runs once per frame on seqParallel (worker) when the `mt_config` mtLUA_GC flag is set (default), so it still shows under `tasks.gc_ms` (gc_steps 1.0) and inside game_thread_ms; `main.gc_ms` only moves when mtLUA_GC is off.
- Overhead measured: no-window FPS new vs pre-change exe within noise (≈1475-1500 vs ≈1490-1505 fps, interleaved runs); window active vs no window in the same session ≈1394 vs 1396 fps.
- Measured (fake_start, uncapped, noisy shared machine): baseline ≈1.3 ms frame, Lua 0.24 ms (≈15 outermost entries/frame, mostly scheduler_rt); a 10 ms busy `actor_on_update` callback → Lua 11.5 ms, frame 14.3 ms; 20k-table garbage per update → Lua 11.2 ms, heap growth ≈890 KB/frame; both back to baseline after removal. 30 fps cap: limiter 32 ms, busy 1.8 ms.
- Phase/section enums in mcp_perf.h are the place for new main-thread sections.

# Lua profiler (game_lua_profile)
- = a perf window with `perf.start {"seconds","lua_profile":"time"|"calls"|"alloc","top":N}`; the report gets a `lua_profile` object built by xrGame `src/xrGame/mcp_lua_profiler.cpp` through `mcp_perf::lua_prof` {start, frame, stop, report} (all main thread, no Lua running). Supervisor `game_lua_profile` (block after game_perf) = that window + game_perf's Lua/GC/heap fields.
- Prior art checked: the fork's LuaJIT (2.0.4 + backported 2.1 profiler) has `jit.profile` / `luaJIT_profile_start` (C callback, Windows timer thread, `iN` = exponential-jitter Sleep, real tick ≈1-2 ms) and `jit.allocprof` (lj_allocprof.c, byte-sampled allocation per function); GAMMA ships `luamod/perf_luaprof.script` on jit.profile (file report, no entry/thread split). No engine profiler command.
- Decided: exact entry timing + gated sampling. `pcall_hook` now gets `(L, fn index, enter)` (fn = called function's stack index in pcall, 0 for resume); the hook (`mcp_lua_profiler_hook`, wraps `mcp_perf::lua_hook`, which now returns outermost + duration) keys outermost entries by the called function (pointer cache → `src:linedefined` via `lua_getinfo(">S")`; resume = coroutine's outermost frame).
- Decided: LuaJIT gate `luaJIT_profile_gate(volatile long*)` (lj_profile.c/luajit.h): ticks are dropped while no thread is inside a luabind entry. Without it every tick taken in engine code is delivered at the next Lua bytecode and charged to whatever runs first (perf_luaprof's documented flaw).
- Sampler = Lua `jit.profile.start('i1', <C function sample_cf>)` (run as a chunk from C): lib_jit calls it via lua_pcall on its own thread and then aborts any trace being recorded. Decided over a raw `luaJIT_profile_start` C callback: the fork's profile hook (lj_dispatch_ins) skips `lj_trace_ins` for the sampled instruction, so a C callback without that abort can leave a corrupt trace. The callback walks the profiled thread's stack (`lua_getstack`/`getinfo "Sn"`, read-only, ≤48 Lua frames, C frames skipped): leaf = self, each distinct frame = inclusive; ms = samples × (exact armed Lua time of that thread / its samples). vmstate per sample (jit/interp/c/gc/compiler); gc_pct per function = its self samples in GC state (allocation pressure, free).
- Callback listeners: the innermost frame that is `axr_main.make_callback` (src:linedefined taken at arm time, else call-site name make_callback in an axr_main source) marks the frame above it as the listener (inclusive `listen` samples). Callback names come at report time from make_callback's `intercepts` upvalue (name → {function or table with a method of that name}); a listener registered for several callbacks is shown as "a|b", other frames above make_callback (e.g. _g_patches spairs iterator, or a listener unregistered meanwhile) as "(dispatch iterator or unregistered)". No values are pushed inside the sample callback.
- Main vs worker split uses `mcp_perf::lua_on_main()` (same rule as game_perf); worst frames (5 slowest window frames) mix both threads: exact entry ms + sampled leaf ms scaled to that frame's Lua time.
- Only window frames count (`mcp_perf::in_frame()`): Lua during loading frames / before the first frame is dropped, as in game_perf. Sampler time is subtracted from entry times (`tl_overhead`) and reported as `sampler_ms`; game_perf's lua_ms still includes it.
- Names: sampled call-site name ranked global/method 3 > field 2 > local/upvalue 1 (reported with "(local)": the caller's variable, e.g. make_callback's `func_or_userdata`); at report time rank<2 names are replaced from a rawget scan of `_G[<script basename>]` and of `_G` for functions with the same short_src+linedefined (`module.func`). luabind class methods (binder update) stay unnamed.
- calls mode: `lua_sethook(LUA_MASKCALL)` counting Lua-function calls per `src:linedefined`, JIT flushed+off for the window (hooks do not run inside traces), refused if a debug hook is already set. alloc mode: `lj_allocprof_start(L,1)` (internal C API, struct mirrored), JIT off, harvested at stop; no time sampling then (allocprof and jit.profile are mutually exclusive). JIT restored only if `jit.status()` was on.
- Refused when a script already runs jit.profile/allocprof (e.g. perf_luaprof): our start would silently take the profiler over.
- Level change / load: `CScriptStorage::reinit` and `~CScriptStorage` call `mcp_lua_profiler_close(L)` before `lua_close` (stops the timer thread, hooks; clears the pointer cache); the next window frame re-arms on the new state (`lua_state_closes`). Without this the timer thread would touch a freed global_State.
- Gotcha: functions are identified by `short_src:linedefined`; two functions defined on the same line (one-line lua.exec chunks) merge. Pointer cache can mis-attribute if a function is collected and its address reused (entries are long-lived functors/binder methods).
- Gotcha: a tick taken in an entry's trailing C code is delivered at the next interpreted bytecode, possibly in the next entry; JIT traces deliver at trace exit (vmstate jit = floor). Lua run by raw lua_pcall (script loading, lua.exec) is never sampled (gate closed) but its pending samples can land there.
- Gotcha (crash found in verify): this fork's `lua_getinfo(L, ">S")` returns 0 WITHOUT popping when the value is not a function. luabind pcalls callable userdata (class constructors, e.g. `CObjectItemScript::server_object` → m_server_creator), so an unconditional push+getinfo left an extra value and shifted the call ("attempt to call a string value" on the next spawn of a new class). Always check `lua_isfunction` first; such entries are labelled `[callable object]`.
- Gotcha (testing): the MCP SDK's stdio_client passes only a whitelist of env vars to the server, so env switches set in the client never reach the supervisor/game; and PowerShell `Set-Content -Encoding utf8` writes a BOM that breaks exec'd Python scenario files (a silent no-op run whose stale log looks like a result).
- Measured (l01_escape, new game, uncapped, shared machine): idle main Lua ≈0.26-0.29 ms (bind_stalker actor update ≈88 %, actor_on_update listeners bind_campfire / actor_effects HUD_fog on top), worker Lua ≈0.15 ms (xr_motivator, sim_squad_scripted update, simulation_objects get_server_entity). Profile entries total = game_perf main lua_ms within 1 %. Hog A (10 ms busy listener) → #1 self 9.8 ms/frame, listener of actor_on_update, entry bind_stalker 10.2 ms, calls mode calls_per_frame 1.0. Nested (wrap → inner 5 ms) → inner self 5.0, wrapper self ≈0 / listener total 5.25. 20k-table garbage listener → gc_pct 79 %, vmstate gc 75 %, alloc mode 1350 KB/frame attributed to it (97 %), game_perf growth 1110 KB/frame.
- Overhead: idle FPS new vs pre-change exe within noise (≈472-488 vs ≈423-451 fps, same scene, consecutive launches); time mode costs ≈1-3 % FPS (475/466 vs 479-484 idle in the same session), sampler ≈0.001 ms/frame idle (≈450 gated samples per 5 s); calls mode ≈ the JIT-off interpreter cost; alloc mode ≈25 % FPS (98 vs 130 fps with the garbage hog).
- perf.start while a window runs restarts it (profiler stopped and re-armed, data of the old window dropped); a poller of the old window then gets the new window's report. Verified: refusal while a script runs jit.profile (the script profiler keeps running), restart, level change mid-window (`lua_state_closes` 1, re-armed, JIT on and no debug hook afterwards), quit while profiling (graceful exit 0).
- Profile totals vs game_perf: equal within ≈1 % normally; across a level change the profile is ≈10 % higher because Lua of a frame interrupted by a loading frame is kept by the profiler but dropped by game_perf.
