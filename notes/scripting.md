# Lua scripting
- `run_string` = `CCC_ScriptCommand` console_commands.cpp:1949: with level → `script_process(eScriptProcessorLevel)->add_script(...)` (runs on a later frame); no level → `luaL_loadbuffer`+`lua_pcall` on `ai().script_engine().lua()` :1969-1976 (synchronous).
- `run_script` console_commands.cpp:1911; `CScriptProcess::add_script` xrServerEntities/script_process.cpp:101.
- Errors: `print_output` / `on_error` script_engine.cpp:654.
- Engine→Lua calls: `script_engine().functor("module.func", f)` script_engine.h:155 (e.g. Level_input.cpp:188).
- LuaSocket exists (3rd party/lua-extensions/luasocket) but only opened with `lua_debug` (script_storage.cpp:449-464).
- Gotcha: script engine is in xrGame, not xrEngine — engine-side server needs an xrGame-registered handler for Lua.
- Lua threading: no Lua lock exists. Phase guarantee: worker Lua (GameThread scheduler/seqParallel/seqFrameMT, parallel LuaGC) is submitted after `FrameMove` and joined by `secondary_tasks.wait()` at the end of `on_idle`, so seqFrame handlers (incl. MCP) own the state exclusively.
- `lua.exec` (xrGame/mcp_lua.cpp): readiness = `g_ai_space && ai().script_engine().lua()` (never call `ai()` blindly: it creates CAI_Space). Compiles `return (function(...) return ... end)(<code>\n)` first (keeps the chunk frame; plain `return f()` is a tail call that drops error position/traceback), else `<code>`; chunk name `=lua.exec`; `lua_pcall` with `debug.traceback` (C `luaL_traceback` fallback); `lua_settop` restores the stack. Raw pcall bypasses luabind pcall callback/`Debug.fatal`; errors inside engine→Lua callbacks triggered by the code still use the engine paths.
- `print` is LuaJIT's base print (stdout), not the log. During `lua.exec` only, the global `print` is swapped for `log_print` (tostring'd args, tab-separated, `Log`) and restored after the pcall (also on error); the old function sits on the stack meanwhile. Game scripts keep the stock print.
- debug lib is open (luaL_openlibs; USE_LUAJIT_ONE undefined).
- Release builds (LUABIND_NO_EXCEPTIONS) make every Lua error raised inside an engine->Lua luabind call (callbacks, binders, add_call, functors) fatal: luabind pcall uses `lua_pcall_failed` as the error handler, which Debug.fatal's ("LUA error: ... Check log for details"). The CScriptCallbackEx catch blocks are dead code. Not changed for MCP (would leave luabind returning garbage).
- Non-fatal script errors: script threads (`run_string` with a level, `CScriptThread` ctor/update), console run_string without a level, `load_buffer`/`do_file` (syntax/load errors; detail only with -dbg, else "! [ERROR] --- Failed to load script"), `lua_error_not_crash` (busy-hands). print_output with an error code always logs `! [SCRIPT ERROR]: <msg>`; script_log/print_stack lines need Core.isDebug() (-dbg).
- MCP hooks `mcp_script_error(L, kind, script, msg)` (xrGame/mcp_events.h, one line before each report): kinds callback (lua_pcall_failed, traceback at level 1), luabind (lua_error), cast (lua_cast_failed), panic (fatal); thread (lua_resume failure; traceback of the dead coroutine pushed on the main state), thread_start, console, load, luabind_not_crash (non-fatal). file:line parsed from "path:N:" in the message, else the first Lua frame.
- `level.add_call(function() return true end, function() error('x') end)` from lua.exec = quick fatal script error (callback kind); per-frame non-fatal errors: an actor_on_update callback that runs `get_console():execute("run_string error('x')")` (message `console_command:2: x`, kind thread).
