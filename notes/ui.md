# UI (MCP cursor, ui.tree, game_ui / game_ui_click)
- UI space is 1024x768 stretched over the whole back buffer (also 16:9): `CUICursor` maps client px * 1024/clientWidth; window rects (GetAbsoluteRect) and hit tests use the same space, so screenshot px = ui * image/(1024,768).
- Decided (virtual cursor): `CUICursor::m_mcp_owned` = Device.IsSilent() at start; `McpMoveTo` sets owned + a pending target that the next `UpdateCursorPosition` applies (vPrevPos stays the old position, so scroll/drag deltas work). Owned: never `GetCursorPos` (win-cursor branch skipped) and `SetUICursorPosition` never calls `SetCursorPos`; real/raw mouse deltas still move the virtual cursor relatively.
- Decided (-showwindow policy): the real mouse drives the UI cursor (Windows cursor, unchanged) until the first MCP `cursor` step; then MCP owns it (real mouse deltas move it relatively, the Windows cursor is never read/moved) until `{"cursor":"release"}`, input.release_all or a client change (mcp_input release_all -> hook `cursor_release`). Silent runs stay owned. Not verified live (a -showwindow run steals focus from the user); code-read only.
- Non-MCP runs: owned is false and the hooks are only registered with -mcp_port, so CUICursor/Level_input behave as before (code-read).
- `CLevel::IR_OnMouseMove` recentred the real cursor (`SetCursorPos`) after every in-game mouse move incl. MCP `mouse` steps; skipped when `Device.IsSilent()`.
- input.run step `{"cursor":[ux,uy],"ms":N}` (UI space; glide over ms; done a frame after the last move so the UI's focus/hover Update runs before a following click) and `{"cursor":"release"}`; hooks `cursor_get/cursor_move/cursor_release` in `mcp_input::game_hooks`, implemented in xrGame/mcp_ui.cpp. Move = `McpMoveTo` + `pInput->CurrentIR()->IR_OnMouseMove(dx,dy)` when the cursor is visible (same path as a real move: CDialogHolder::IR_UIOnMouseMove -> OnMouseAction MOVE); hidden cursor -> only placed (no camera turn). Clicks are the existing mouse key steps (LMB/RMB/MMB).
- Double click = two taps with `wait 40` between (CUIWindow turns a LBUTTON_DOWN into DB_CLICK within 250 ms on another frame); verified: double-click on an Anomaly inventory cell equips the outfit.
- `ui.tree {root, max_nodes (3000), max_depth (40)}` (xrGame/mcp_ui.cpp) -> `{screen, ui_size, cursor, dialogs:[{root,class,script_class,node}], nodes:[{i,p,path,d,class,script_class?,name?,kind,text?,rect,...}], truncated?, ms}`; flat DFS of shown windows; path = dialog index + child indices (stable while the UI is unchanged). Roots: top = main menu top dialog when the menu is active else CurrentGameUI top dialog; menu, game, hud (CurrentGameUI()->GetWindow()), all.
- Kinds by smart_cast, most derived first: question (CUIQuestionItem), answer (CUIAnswerItem: children m_text, m_name), tab, check, edit, track, combo, list_item, cell (CUICellItem / Anomaly script cells), button, tabs, talk_options/talk_log (scroll views named ---UIQuestionsList/---UIAnswersList), list, scroll, cell_list, menu, static, menu_item (CUITextWnd under CUIMMShniaga = main/ESC menu entries), text, window. Children of button/check/tab/track are not emitted (their own visuals); a button without text takes its first child text.
- CUIStatic::TextItemControl() creates the text control lazily, so text is read via the protected `m_pTextControl` (member-pointer accessor); same trick for CUICustomEdit::m_bInputFocus and CUITrackBar::m_b_is_float.
- clip: ancestors that clip (IsClipEnabled -> GetClipRect, CUIScrollView, CUIDragDropListEx) intersect; node outside -> clip "out" (supervisor hides them: an Anomaly trader bag has ~800 scrolled-out cells), partly -> "partial".
- Anomaly inventory/loot/trade (`UIInventory` script window): cells are Lua `utils_ui.UICellItem` objects (`.cell` CUIStatic, `.section`, `.ID`, `.childs`) inside `self.CC[name].cell`; a guarded Lua chunk maps the static (luabind::object_cast_nothrow<CUIWindow*>) to item {section, name, id, count, container (actor_bag, actor_equ, actor_quick, actor_trade(_bag), npc_trade(_bag), ...)}. Equipment/quick-slot containers are flagged disabled but take clicks (the script hit-tests by cursor), so game_ui_click ignores enabled for cells.
- Anomaly inventory reacts to drag/drop by hovered cell (UICellContainer:GetCell_Focused, m_bCursorOverWindow): drop onto a cell or slot. Equipping a helmet/outfit or eating plays an animation that closes the inventory (not a bug).
- Verified 2026-11-16 (vanilla, game_input drag/click on cell centers from game_ui): drag `kobra` onto equipped `wpn_ak74` attaches it (slot 3 becomes `wpn_ak74_kobra`, new object id, scope item consumed); drag of non-fitting `acog` does nothing (fit = weapon ltx `scopes` list, e.g. ak74: 1p29,kobra,ps01); double-click an outfit in the bag equips, double-click the equipped outfit unequips (both close the inventory for ~2-3 s of animation); RMB on the equipped outfit lists `remove suit / details / disassemble [!] / drop`, `remove suit` unequips; RMB on the scoped AK lists `unequip / unload / details / disassemble [!] / detach scope / drop`. A given weapon auto-equips into a free slot. game_ui `kind` filter is a list (`["cell"]`). GAMMA: not run separately; user treats it as covered (same inventory UI).
- Context menu (RMB on a cell) = script `UICellProperties` with `UICellProperties_item` (CUIListBoxItem) entries use/separate/details/drop; LIST_ITEM_CLICKED runs the action. Verified drop (item on the ground) and use (bread eaten).
- Main menu (CUIMMShniaga) takes a click only after its highlight slid onto the hovered entry: click right after the move does nothing; game_ui_click waits 400 ms (UI_MENU_HOVER_MS) for menu_item, game_input click has `"hover": ms`.
- Options (ui_options script): left tree entries are CUICheckButtons with a sibling text label -> supervisor `label` (next sibling text of a text-less interactive widget); combos open a CUIListBox of list_items; track bar drag works (FOV 75 -> 130).
- 3D PDA: CUIPdaWnd widgets are disabled until the first LMB/aim on the PDA (CPda::Action kWPN_FIRE enables it); its UI is drawn onto the device texture, so px rects do not match the screenshot, but UI-space clicks hit (verified tab switch to Relations).
- Talk: options = CUIQuestionItem in UIQuestionsList order; `m_s_value` = phrase id (dialog id in the topic list); number = position (1..9, 10 = key 0 via SetAccelerator(DIK_ESCAPE+n)); finalizer options also take ESC/use. ui.tree question nodes carry `id`; game_ui talk.options list all options (index = on-screen number, `clip: out` when scrolled out; game_ui_click(option=) refuses those -> game_talk). Answers text keeps the game's literal "
" (supervisor converts). Verified 3 levels with Sidorovich by index and by text, trade via option 1, buy (money 5000 -> 3606).
- Cost: ui.tree 0.1-1.7 ms (menus, inventory), ~6 ms for an Anomaly trade window (~850 nodes); 200 calls while inventory/PDA/menu toggled + calls across a same-level load: no errors, no crash.
- Talk (goal 23): task/reward lines arrive as iconed entries (CUIAnswerItemIconed, ui.talk `info: true`, no speaker: "New mission:", "Money lost:", "Needs:"). Fanatic: decline training (id 2) -> topic `dm_ordered_task_dialog` -> accept = phrase id 2 ("I'll do it.", action dialogs.npc_give_task) -> "Thanks." (id 4) back to topics; `actor_break_dialog` (final) closes.
- `ui.talk {since}` (goal 26, mcp_ui.cpp): CUIGameSP::TalkMenu read-only via member-pointer accessors (talk_acc, script_acc): {open, top (talk window is the top dialog), partner {id,name,section,character (specific char id),profile,community,trade,upgrade}, topic, dialog, pending (m_bNeedToUpdateQuestions: options rebuilt next frame), options_rect, options [{n,key,id,dialog,text,final,ends,actions,give_info,disable_info,replies[{id,actions,...}],rect,clip}], log [{i,speaker,text,actor|info}] from index since, log_count, ms}. No Lua calls.
- Option effects come from the dialog graph (CPhraseDialog::get_sd()->m_PhraseGraph, public): `ends` = no next phrase or no partner reply leads on; the consequences usually sit on the partner's reply phrase (`replies`: e.g. Fanatic training reply 3 = become_actor_companion/give_task, Sidorovich `dm_init_trader` reply = dialogs.npc_is_trader which opens trade).
- NPC replies are synchronous (CAI_PhraseDialogManager::ReceivePhrase -> AnswerPhrase in the same frame as the click/key); UpdateQuestions runs on the next frame. Choosing a phrase with a single all-dummy reply auto-says it.
- Supervisor `game_talk` (UI tools block): talk_get = heartbeat + ui.talk (+ state.get only when the talk is not on top: mode = ui.dialog script_mode/menu_mode/kind, e.g. `trade` = UIInventory over the talk); choose = number key for n <= 10 (works when scrolled out), else wheel at the options list (+1 = up) until the option is fully inside options_rect, then cursor + LMB; settles by polling ui.talk(since) until not pending and log/dialog/options changed (or closed / other mode), timeout 3 s -> warning.
- Talk first-click drop (goal 41): `CUITalkWnd::AskQuestion` returns at once while m_bNeedToUpdateQuestions (set by InitTalkDialog on open, any info portion given/disabled during the talk, ReceivePhrase, trade/upgrade close); the old option buttons stay until the rebuild, so a key then does nothing. game_talk now waits (<= 2 s) until ui.talk pending is false before picking, and repeats a press once when nothing changed (log_count, dialog, option ids, not pending) after 1 s (chose.retried). Not reproduced live: vanilla Sidorovich, game_use -> game_talk read -> topic 2 chosen on the first press.

- Talk closes by itself when the partner dies (game_kill) or is moved ~30 m away (set_npc_position): ui.talk open false, game_talk choose -> clear error. Cost: ui.talk 0.01-0.25 ms engine; game_talk read ~31 ms (two main-thread round trips at the 30 fps cap); 200 reads vanilla/GAMMA: no errors, no script errors. A choice takes ~150 ms (key) / ~570 ms (scroll+click).
- Text: to_utf8 maps cp1251; byte 0x98 (the game font's bullet in txr_routes options) has no cp1251 char and comes back as U+FFFD.
