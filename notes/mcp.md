# MCP layer
- Decided: agent ⇄ MCP stdio ⇄ Python supervisor (`mcp/`, official `mcp` SDK, PyInstaller single exe later) ⇄ TCP newline-delimited JSON-RPC ⇄ engine.
- Decided: engine server is localhost-only, one client, off unless `-mcp_port N` is passed.
- Decided: net thread only parses/queues; all game/Lua/console work runs on the main thread in a pureFrame.
- Decided: engine pushes every log line as an event so the supervisor survives crashes with full history.
- Decided: MT branch only (`dev-mt-mcp`); supervisor lives here permanently, no non-MT port.
- Methods: `ping`, `engine.info`, `engine.heartbeat`, `log.tail`, `console.exec`, `lua.exec`; events: `log`, `crash`, `game`.
- Engine server: `src/xrEngine/mcp_server.{h,cpp}` (namespace `mcp`); started in `Startup` (x_ray.cpp) after `Init_Discord` when `-mcp_port N` (`ECoreParams::mcp_port`), `mcp::stop()` right after `Device.Run()`.
- Protocol v1: one JSON object per line. Req `{"id","method","params"}` → `{"id","result"}` / `{"id","error":{"code","message"}}`; events `{"event","data"}`. Codes: -32700 parse, -32600 invalid, -32601 no method, -32603 handler error.
- Net thread (std::thread) owns all socket I/O: accept → select(5ms) loop that flushes outbox then recv; one client, re-accepts after disconnect. Max line 1 MB.
- Main thread: `frame_hook` on `Device.seqFrame` (REG_PRIORITY_LOW) drains inbox, runs handlers. `AddSeqFrame`/`RemoveSeqFrame` are private to CRenderDevice.
- `mcp::register_method(name, handler)`: handler `bool(LPCSTR params_json, xr_string& out)`; true → out is result JSON text, false → out is error message. Main thread only. ENGINE_API, so xrGame can add methods.
- `mcp::send_event(name, data_json)`: thread-safe, queued to the net thread; dropped with no client. Responses are tagged with a connection id so a stale client's replies are dropped.
- Builtins: `ping` → "pong"; `engine.info` → protocol_version, version ("X-Ray Monolith vX (build N, date)"), mt:true, level (`g_pGameLevel->name()` or null).
- Gotcha: xrEngine builds with exceptions off → nlohmann auto-uses abort-on-throw; only use non-throwing APIs (`parse(s,nullptr,false)`, `find`, `is_*` checks, `dump(..., error_handler_t::replace)`).
- nlohmann/json v3.12.0 vendored at `src/3rd party/nlohmann/json.hpp` (+ LICENSE.MIT); include only in .cpp files.
- `-mcp_port 0` = ephemeral port (sscanf %d, 0..65535 valid). After listen, actual port (getsockname) is written as `<port>\n` to `<app_data_root>\mcp_port` via `mcp_port.tmp` + MoveFileEx; deleted in `mcp::stop()`. Stale file remains after a crash or failed bind.
- `engine.info` also returns `pid` (GetCurrentProcessId; used by the supervisor to watch attached games), `frame` (Device.dwFrame), `active` (Device.b_is_Active), `rendered` (Device.dwRenderedFrames), `iconic` (IsIconic main window), `silent` (Device.IsSilent()).
- MCP runs are silent by default: no splash, main window minimized, never takes focus, still renders; `-showwindow` restores normal window/focus/splash (see engine.md).
- Multi-instance: each instance `-fsltx C:\Anomaly\fsgame.ltx -mcp_port 0 -appdata <dir>`; MCP mode never pauses on focus loss.
- Log streaming: `mcp::capture_log()` (called in WinMain_impl right after `Core._initialize` when `-mcp_port`) registers `on_log` via `xrLogger::AddLogCallback`; removed at the top of `mcp::stop()`. Missed: the ~11 lines logged inside `Core._initialize` (CPU, FS init, xrCore build); seq 1 is "Game started: ...".
- Every line gets seq (u64, from 1) and goes into a 10000-line ring (`log_ring_size`, `log_lock`); event `{"event":"log","data":{"seq","line"}}` only while a client is connected. Lock order: log_lock → out_lock.
- Log text: cp1251 → UTF-8 (MultiByteToWideChar 1251 → CP_UTF8); unmapped 0x98 becomes U+FFFD.
- `log.tail`: `{"n":K}` last K lines or `{"since":S}` lines seq > S still held; result `{"lines":[{"seq","line"}],"first_seq","last_seq"}`; first_seq = oldest held (last_seq+1 if empty), last_seq = newest assigned (0 if none). S < first_seq-1 means lines were lost. Missing/invalid params → -32603.
- Backpressure: outbox is a deque; `queue_event` drops the oldest queued event beyond `max_queued_events` (10000); responses never dropped. Net thread sends outside out_lock, so a slow client never blocks the logger. Client recovers gaps via log.tail.
- Reconnect recipe (verified): connect, read events, call `log.tail {"since":<last seen or 0>}`, union by seq → gapless. "* [MCP] Client connected" is the first streamed line of a connection.
- Fixed: `engine.info` crashed while a level was loading (`g_pGameLevel->name()` is empty, so json(null c_str)); it now returns level null until the name is set.
- `console.exec {"cmd"}` → `{"lines":[...],"truncated":N}` (xrEngine builtin, `Console->Execute`, i.e. no history/echo). `lua.exec {"code"}` → `{"results":[tostring each, nil→"nil"],"lines":[...],"truncated":N}`; registered from xrGame (`xrGame/mcp_lua.cpp`, `mcp_register_lua()` in `CGamePersistent::OnAppStart`). Errors → -32603 with message (+ traceback).
- Line capture: `mcp::run_logged(f)` (ENGINE_API) logs `* [MCP] exec #<id>` before f and `... done` after, then waits (cv on log_lock, max 2 s) until on_log sees the end marker; returns ring lines strictly between (FIFO logger queue ⇒ all lines printed during f). Lines from other threads in that window are included. Timeout → partial lines + `! [MCP] exec #N: log lines incomplete`. Markers stay in the log/ring/events.
- ENGINE_API JSON helpers for xrGame (keeps nlohmann out of xrGame): `get_string_param(params,key,out)` (UTF-8→cp1251), `to_json_string(s)` (cp1251→UTF-8 quoted). Handler error messages are converted cp1251→UTF-8.
- Fixed: console `help` crashed in `CCC_Token::Info` (null token list, xr_ioc_cmd.h); null guard added. `help` prints ~1000 lines.
- `run_logged` returns JSON members `"lines":[first 500],"truncated":<rest>` (`max_exec_lines`); handlers wrap it in `{...}`. Lines beyond the cap are still in the ring/events.
- Supervisor (Python, `mcp/anomaly_mcp.py`) → see `supervisor.md`.
- `engine.heartbeat` → `{"frame","loading"}` is answered on the net thread in `on_line` (works while the main thread is hung or loading); loading = `pApp->IsLoading()` (ll_dwReference > 0, accessor added to x_ray.h). Observed: loading true briefly during the fake_start load; dwFrame did not stall there.
- Crash event: `on_crash` is chained into `Debug.set_crashhandler` in `mcp::start` (calls the console's DumpConsoleVariablesOnCrash first; restored in stop). On the crashing thread: FlushLogSync, take `send_lock` (timed 1 s, then kept until exit), drain the outbox (log events) and send it plus `{"event":"crash","data":{"reason","stack","dump"}}` with SO_SNDTIMEO 2 s, then shutdown(SD_SEND) and recv until the client closes (<=3 s) so process exit does not reset the connection and lose data.
- `out_lock`/`send_lock` are `std::timed_mutex` (the crash path never waits forever); the net thread holds `send_lock` per flush. `client_sock` (atomic) is the live client socket.
- Crash triggers used for testing: AV = `lua.exec` `require("ffi").cast("int*",0)[0]` (LuaJIT does not catch the SEH AV); FATAL = `system_ini():r_string("no_such_section_xyz","x")`; hang = `while true do end`; __fastfail = scratchpad remote thread running `mov ecx,7; int 29h` (bypasses all in-process handlers).
- `perf.start` / `perf.report` (frame/Lua timing window) live in `xrEngine/mcp_perf.cpp`, registered in `mcp::start` → see `perf.md`; `perf.start {"lua_profile":mode}` adds the Lua profiler (xrGame `mcp_lua_profiler.cpp`).
- Game events (`src/xrGame/mcp_events.{h,cpp}`, `mcp_register_events()` in `CGamePersistent::OnAppStart`; no-op without `-mcp_port`): event `game` `{"seq","type","time" (unix ms),"frame","data":{...}}`, seq from 1 per process; last 1000 in an xrGame ring (`events.tail`); one std::mutex guards ring + error state, send_event is called under it (lock order mcp_events lock -> out_lock).
- `events.tail`: `{"since":S}` events seq > S still held, or `{"n":K}` the last K -> `{"events":[...],"first_seq","last_seq"}` (same semantics as log.tail). Registered at OnAppStart, so a very early connect may get -32601; the supervisor then fills on the first seq gap.
- `mcp::get_int_param(params,key,s64&)` (ENGINE_API) next to get_string_param.
- Event types: script_error, level_loaded {level, previous = last unloaded level}, level_unloaded, actor_spawned {level,id,name,health,alive}, actor_died {level, killer_id/name/section or killer_id null}, game_saved/game_loaded {name (without .scop, same form for both), file}, menu_opened/menu_closed {level}, task_given/task_completed/task_failed/task_in_progress {id,title (translated),title_id}.
- Level/actor/menu come from a frame poll (seqFrame REG_PRIORITY_LOW, never removed): level loaded = g_pGameLevel with a name and !pApp->IsLoading(); ended by pointer change, loading, name change (a level change can reuse the CLevel address) or a game_loaded hook (loading a save of the same level showed no loading frame); actor_spawned once per (loaded level, g_actor). Death/save/load/task are one-line hooks: CActor::Die, CALifeStorageManager::save/load(LPCSTR), CGameTaskManager::GiveGameTaskToActor/SetTaskState(CGameTask*).
- A level change emits game_saved (autosave) + game_loaded (autosave) between level_unloaded and level_loaded; a new game starts on fake_start (level_loaded fake_start, actor_spawned) then changes level.
- Script error coalescing (engine-side, per kind+message): first occurrence sent at once with traceback; repeats within 5 s only counted, then one event per 5 s window (`count` = total, `since_last` = occurrences it stands for; the flush event from the frame poll has no traceback). >20 new messages per 5 s or >256 keys -> counted into one `kind:"overflow"` event. Fatal kinds are never coalesced. Measured: 600 errors at 30/s -> 5 events.
- `screenshot.begin` / `screenshot.get` (request+poll, image base64 inline, max response ~600 KB for a 800 px PNG; JSON-lines has no outgoing size cap) -> see `render.md`.
- `input.run {"steps":[...]}` → `{"id"}` (validated up front: unknown names → -32603 with the valid list); runs from the next frame. `input.status {"id"}` → `{id,done,started,elapsed_ms,frames,cancelled?,warning?,held}`; without id → `{running:[...],held:[names]}`. `input.release_all` → `{released,cancelled}`. Last 32 finished sequences are kept. See input.md.
- `mcp::client_id()` (mcp_server.h, xrEngine-internal) = current conn_id, 0 when no client.
- Registration from xrGame: `mcp_register_input()` (xrGame/mcp_input.cpp, OnAppStart) → `mcp_input::init(hooks)` (ENGINE_API; no-op without -mcp_port).
- `world.objects` / `world.object` (nearby objects, one object's detail) -> see world.md; registered from xrGame/mcp_world.cpp.
- `state.get` (game state snapshot) -> see gamestate.md; registered from xrGame/mcp_state.cpp. JSON built with a local flat-object builder (`jobj`) over `mcp::to_json_string` (no nlohmann in xrGame).
- `time.get` / `time.pause` / `time.step` / `time.factor` (MCP pause, fixed-dt steps, time_factor; reset on client change) -> see time.md; registered in `mcp::start`.
- `ui.tree` (flat dump of visible windows) registered from xrGame/mcp_ui.cpp (`mcp_register_ui()` in OnAppStart); input.run `cursor` step drives the virtual UI cursor -> see ui.md.
